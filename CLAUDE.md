# Mariana Engine (WebGPU)

C++20 game engine + ImGui editor on WebGPU (Google Dawn). One codebase builds native (Windows/MSVC primary) and web (Emscripten → `index.html`, deployed to GitHub Pages from branch `2025`). Author: Noel Pellkvist.

## Build

- Native: `cmake -B build` then `cmake --build build --config Debug --target MarianaEditor -j4` (VS Code task "build Debug"; `--target MarianaPlayer` / "build Player Debug" for the player). Output `build/bin/Debug/MarianaEditor.exe` and `MarianaPlayer.exe`.
- Web: `emcmake cmake -B build-web` then `cmake --build build-web -j4`. Output `build-web/bin/index.html` (+ .js/.wasm/.data) for the editor, `build-web/player/index.html` for the player: a standalone site (index.html/.js/.wasm/.data, nothing else) to upload as is, kept out of `bin/`, which is what Pages publishes. Serve it over http(s); WebGPU needs a secure context (https, or localhost). `mariana_web_app()` (`cmake/MarianaWeb.cmake`) sets the shell (`editor/shell.html`, `runtime/shell.html`), ASYNCIFY, GLFW3, a 1 MB stack (Jolt asks for it) and preloads the engine's resources plus the app's folders or single files (at their absolute paths; files as `path@path`; `.mariana` cache folders are excluded); the engine adds `-fexceptions` (public, to compiling and linking: without it at link time catching is off and the first caught exception terminates) and `FLECS_NO_THREADS`.
- CI: `.github/workflows/pages.yml` (emsdk 4.0.16) builds web and deploys `build-web/bin` to Pages. The tests are three native console programs (no window or GPU; their mains send failed debug checks to stderr instead of a dialog). `MarianaEngineTest` (`engine/tests/EngineTest.cpp`) runs `engine/tests/*Scenarios.hpp` (`ProfilerScenarios.hpp`: scopes nest in order with self times, a worker thread's scope, counters add up, GPU times land on their frame, the ring keeps 600 frames, paused frames aren't kept, the trace parses; and from `tests/TypeScenarios.hpp`: the definitions load and declare every library member the bindings define, the Sandbox's scripts check clean in strict mode, a script with planted mistakes gets a problem on exactly those lines, autocomplete offers an entity's methods after `:`, component names inside `Get("`, a component's fields after `.`); its main sends failed debug checks to stderr instead of a dialog; the web harness runs them too.
- Games: File > Build (Build Settings..., Build Ctrl+B, Build and Run Ctrl+Shift+B) or `build/bin/<config>/MarianaExport.exe --project <folder> [--profile <name>] [--list]` builds a project's build profile (`BuildProfiles.json`) into `<project>/Builds/<profile>` (see Building games below). Another console test, natively only: `MarianaExportTest` (`export/tests/ExportTest.cpp`): what the Sandbox's Windows profile packages (Playground.scene, CarConcept's folder, Rumba.glb, Dancer.animgraph, the Scripts folder; not Sponza or `.mariana`), the Player.json it writes, profiles saved and read back, staging copies the files.
- Each target globs its own `source/**/*.cpp` — new .cpp files need a CMake re-configure (CONFIGURE_DEPENDS handles it on build).
- Resource paths are given as `"/Shaders/x.wgsl"` and resolved by `FileSystem` (`Mariana/Foundation/FileSystem.hpp`): a list of root folders searched in order, the app's (`AddRoot`, the latest first) before the engine's (`MARIANA_ENGINE_RESOURCES`, a compile definition of the engine; `SetEngineRoot`). `FileReader`, `Texture::LoadTexture`, the window icon and effect/pipeline files go through `Resolve`; `RenderPipelineDesc::Save` through `ResolveForWrite` (the existing file, or new under the first root). A project can override an engine file by putting one at the same path. OS paths (e.g. what the Assets browser drags) are not resource paths; `ToResourcePath(file)` turns one under a root back into one (matching without case on Windows, keeping the file's spelling).

## Layout

- `engine/` → static library **MarianaEngine**: everything a game needs at runtime. Public headers in `engine/include/Mariana/<Module>/`, included as `<Mariana/Module/X.hpp>`; sources in `engine/source/<Module>/` (private headers too, e.g. `Graphics/Init.hpp`, included as `"Graphics/Init.hpp"`). Modules, each using only the ones before it: `Foundation` (Logger, `Profiler`, FileReader, FileSystem, `Image` (CPU RGBA8: Load, SavePNG, Downscale by halving with alpha-weighted colors), `FileWatcher`, `TaskQueue`, `GameClock`), `Graphics` (GPU context, Buffer + layouts, Texture, Shader2, Material2, Mesh, Renderpass, NativeGPU), `Platform` (Window, IInput), `Scene` (ECS, Prefab, `Transform.hpp`: `LocalMatrix`/`WorldMatrix` from the LocalTRS chain, current before `Scene::Update`; physics, scripting and IK use it), `Assets`, `Geometry` (StandardVertex, MeshBuilder, Primitives), `Animation` (Skeleton, AnimationClip, Pose, AnimationGraph, Animator, Skin), `Rendering` (Renderer, RenderGraph, SceneRenderer, SceneView, SceneCamera, Effect, RenderPipeline, StandardPBR, SkyLight, ICamera, MaterialAsset, BuiltinAssets, Components), `Importers` (GLTFLoader, ImageImporter, MaterialFile, AnimationGraphFile); `Mariana/Application.hpp` sits on top. glm, Dawn and GLFW are public dependencies, flecs/json/stb/tinygltf private.
- `physics/` → static library **MarianaPhysics** (see Physics below): rigid bodies and colliders on Jolt, for apps that want them. Public headers in `physics/include/Mariana/Physics/`, sources (and the private `JoltCommon.hpp`) in `physics/source/`. Links MarianaEngine publicly and Jolt privately; no UI.
- `scripting/` → static library **MarianaScripting** (see Scripting below): game code in Luau. Public headers in `scripting/include/Mariana/Scripting/`, sources (and the private `Bindings.hpp`) in `scripting/source/`, the script API for script writers in `scripting/API.md`. Links MarianaEngine and MarianaPhysics publicly and Luau privately; no UI. `scripting/tools/` → static library **MarianaScriptTools** (the scripts' types, checking, autocomplete and tokens on Luau.Analysis; the editor and the test link it, the player doesn't).
- `export/` → static library **MarianaExport** (see Building games below): build profiles, the files a game takes, running tools and the exporter; on MarianaEngine; the editor links it, and `export/tools/ExportMain.cpp` is the `MarianaExport` command line tool (natively).
- `editor/` → executable **MarianaEditor**: `EditorApp`, the ImGui layer (`Editor/GUI.hpp`), windows, inspector drawers, editor camera, ImGuizmo, the physics UI (`Editor/Physics/`), the scripting UI (`Editor/Scripting/`). Headers in `editor/include/Editor/`, sources in `editor/source/`. Links MarianaEngine + MarianaPhysics + MarianaScripting + imgui.
- `runtime/` → executable **MarianaPlayer**: runs a project without the editor or any UI. `PlayerApp` (an `Application`) reads the project's `/Player.json` (`PlayerConfig`: window, pipeline (empty: the scene's, else the default), camera position/target/orbit speed, prefabs or primitives (cube/sphere/plane/cylinder/capsule with a `color`) to spawn with position, Euler `rotation`, scale (a number or per axis), `faceCamera` to turn a prefab's +Z front toward the camera, presets (car/motorcycle/tank/playground/character/course/chain/door/spinner/wrecking ball/pool/ragdoll/flag/drape/jelly/balloon), and a `physics` block (`body` static/kinematic/dynamic, `collider` box/sphere/capsule/cylinder fitted on the root, mesh/convex on every mesh, or none; `mass`, `friction`, `bounciness`, `velocity`; format in `PlayerApp.hpp`), and `"vehicle": "car"` to rig a prefab as a drivable car (`VehiclePresets::RigCar`), `"ragdoll"` to give an animated prefab a `Ragdoll` (a mode, or an object with `mode`, `mass`, `limpOnImpact`, `knockback`, `knockbackLift`), and `scene`, a scene file loaded first with its lighting (the spawns go on top); vehicle and character presets get the driver scripts; `camera.follow` gives a scene without a camera one with ChaseCamera.luau; `profile: true` logs every 5 s the average CPU and GPU ms and the 8 scopes with the most self time (`PlayerApp::LogProfile`; on the web in the console)), sets up the renderer, scene renderer, one scene view, effects, scripts, animation and physics (always running, with the project's `/Physics.json` if it has one) like the editor, and draws through the scene's first camera entity (`SceneCamera`, as the editor's Game view), else a `PlayerCamera` (look-at, optional orbit; Player.json's `camera`). Headers in `runtime/include/Player/`. `main.cpp` finds the game first: an exported game's `data/game` and `data/engine` next to the exe (`FileSystem::ExecutableDirectory`; `SetEngineRoot`), or `/game` in the page's file system on the web, else the compiled-in project; `--check` prints whether Player.json, the engine's shaders, the pipeline, the icon, the scene and every file the scene uses are found, and exits without a window; an exported game started from Explorer drops the console Windows made for it (`Console.cpp`). On the web, `MarianaPlayerRuntime` (built only when asked for, into `player-runtime/`) is the same player with only the engine's resources, its page loading `game.data.js` before the player. Its web build packages only what `Player.json` uses (CMake reads it with `string(JSON)`: Player.json, the project's Physics.json if any, a project-local pipeline, the scene and every file its `dependencies` list, each prefab; a `.gltf` with its whole folder, a `.glb` with its `.materials` folder (`mariana_player_add_file`), and the project's whole `Scripts/` folder (presets get scripts no scene names); editing Player.json or the scene re-configures) and uses the minimal `runtime/shell.html` (black page, canvas scaled to fit with CSS only, loading percentage).
- The engine never includes editor code or ImGui; keep it that way (its include path has no editor folder, so a stray include fails to build). Neither do MarianaPhysics and MarianaScripting, and the engine knows nothing of physics or scripting.
- Builds of a project (`Builds/`, and `/build-web-release/`) are git-ignored. Resources: `engine/resources/` (Shaders, Effects, Pipelines, the default sky in Textures/skybox), `editor/resources/` (font, window icon, `Thumbnails/`: the thumbnail pipeline, its tonemap effect and shader), `projects/Sandbox/` (sample content: Models incl. Sponza and CarConcept (CC BY 4.0, credited in its `README.md` and the repo README), Textures). The editor's `main.cpp` adds the editor and project roots; `MARIANA_PROJECT_DIR` (editor compile definition) is the project it opens. `editor/imgui.ini` is the editor layout (`io.IniFilename`, `MARIANA_EDITOR_DIR`).

## Architecture

Entry: `editor/source/main.cpp` → `EditorApp().Start()`.

### Patterns (every module works with the scene the same way)
- **Components** hold what is authored: settings, references, inputs game code sets (a vehicle's pedals, a character's `move`), and what is saved. A module registers its components in its `RegisterComponents()` (and their scene file serializers, in the first module that sees both the component and `SceneFile`: `SceneFile.cpp` for the engine's, `Serializers.cpp` for physics).
- **What a module works out for an entity while running** goes in a runtime component it adds and removes (`ECS::RegisterRuntimeComponent`: never cloned, snapshotted or saved): `WorldXform`/`XformCache` (transform system), `SkinPose` (renderer), `PhysicsBody`/`PhysicsWheel`/`PhysicsSoftBody` (physics); a module that changes what another draws or does says so through a runtime component that module reads (`MeshOverride`: physics' soft bodies, drawn by the renderer). A component may keep private caches only its own code uses, dropped by its copy (the Animator's bound bones, bindings and scratch poses); nothing else writes into another module's component.
- **What lives outside the ECS** (GPU buffers and slots, Jolt bodies, constraints and characters) is owned by the module's object (`SceneRenderer`, `PhysicsWorld`), keyed by entity (or a runtime component's slot), made from the components and dropped when they go. State only that object needs stays in its records (a ragdoll knocked out, a joint broken).
- **Finding entities**: per-frame work over components is a `System` (`Scene::CreateSystem`, a cached query; `cascade` for parents first); finding entities by one component is `Scene::Each<T>`; by name `Scene::FindByName` (the smallest id when names repeat). Where order matters (making bodies, scripts, "the first" camera), it is entity id order. Walking the hierarchy (`ForEachRoot`/`ForEachChild`) is only for what is about the hierarchy: saving, the Hierarchy window, one entity's own subtree (a model's bones, a chassis's wheels, the colliders below a body).
- **Transforms** change only through `LocalTRS` (the `Set*` setters, or writing it and `++version`); `WorldXform` is derived by `Scene::Update`. Whatever moves an entity remembers the version it wrote, so another version means someone else moved it (physics teleports its body there, a wheel takes a new rest pose).
- **Change detection**: version counters where writes go through an owner (`LocalTRS.version`, `WorldXform.version`, `MaterialAsset::Version()`, `AnimationGraph::Revision()`, `IMesh::deformVersion`); a content signature (FNV-1a, physics' `Signature`) for components edited in place, where nothing sees the writes.
- **Structural changes** (adding or removing components) never happen inside a query's callback or while holding pointers into components (moving an entity to another table moves its components and another entity's row): collect, then change (`InspectorWindow::Defer`, physics' sync, `SceneRenderer::Update`'s `SkinPose`s).
- **Frame order** (both apps): input and controls → game systems on game time (`ScriptWorld::Update` (scripts drive vehicles and characters there), animation, `PhysicsWorld::Step`, `ScriptWorld::LateUpdate` (chase cameras)) → `scene.Update` (transforms) → `SceneRenderer::Update` → each view.

- **Globals** (`engine/source/Graphics/Init.{hpp,cpp}`, private to the engine): `instance`, `adapter`, `device`, `surface`, `windowFormat`, `deviceLimits`. `Init()` creates them synchronously via `WaitAny`. Include `"Init.hpp"` from .cpp files only.
- **Pimpl everywhere**: public headers avoid `webgpu_cpp.h`; GPU handles live in `struct Impl` and are returned as `void*` (`GetTextureView()`, `GetBuffer()`, `GetPipeline()`), cast back to `wgpu::*` in .cpp. The exception is `NativeGPU.hpp` (`NativeGPU::Device()`, `SurfaceFormat()`), for code outside the engine that talks to WebGPU itself (the ImGui backend).
- **Application** (`Mariana/Application.hpp`, in the engine): the app base class. Its constructor takes the app's `WindowSettings` (title, size, icon; the engine has no defaults). Owns `Window`, `IInput`, `std::unique_ptr<ICamera> cam` (set by the app), `assets` and `gameClock`. `OnCloseRequested()` is asked when the window's close button is pressed (false keeps it open: the editor asks about unsaved changes, then calls `Quit()`, which ends the loop after the frame). Loop: `Profiler::BeginFrame` → `Window::FollowCanvas` (web: the window follows a canvas the page resized) → `gameClock.Tick(dt)` → `OnUpdate(dt)` (real time) → cam update → `OnGUI` → `OnRender` (each in a profiler scope: Update, GUI, Render) → `input.Update`; natively then Present + `ProcessEvents` (scope "Present": the display wait) → `GpuTimer::EndFrame` → `Profiler::EndFrame`; web uses `emscripten_set_main_loop_arg`.
- **Profiler** (`Mariana/Foundation/Profiler.hpp`, always on): `MARIANA_PROFILE("name")` (a literal or an `Intern`ed name; `MARIANA_PROFILE_NAME(string)` interns) times the rest of a block: the main thread's samples in the order they began (name, start/end in ms since the profiler started, depth), other threads' (TaskQueue tasks: "Background task") appended under a mutex to the frame running when they end; main-thread scopes outside a frame are dropped. `Count(name, value)` adds to a per-frame counter. Frames (index, start, `cpuMs`, `gpuMs` (-1 until known), samples, counters, `GpuPass`es) go into a ring of `kFrames` = 600 unless `SetPaused`; `Frames()`, `Clear`, `Summarize(frames, byName)` = `ScopeStats` per scope as a tree (by parent, name and thread) or by name: calls, total, self (less its children), max in one frame, averaged per frame; `Trace(frames)` = Chrome trace JSON (scopes per thread, frames and GPU passes on tracks of their own, counters). Scopes in the engine and libraries: Update/GUI/Render/Present, Transforms (`scene.Update`), "Scene data" (`SceneRenderer::Update`), "Prepare view", "Encode <graph> <pass>" (`RenderGraph::Execute`), "Encode UI", Scripts / Scripts late / Script reload and one per script call ("VehicleDriver.Update", interned per module and callback), Physics (sync, drive, step (Jolt), contacts, show), Animation, Thumbnails, Scene view / Game view. The editor also times each window it draws ("<name> window"). On the web the browser rounds its clock to 0.1 ms (pages that aren't cross-origin isolated), so single scopes read in 0.1 ms steps there; averages are still meaningful. Counters: Draws, Instances, Triangles, Shadow cascades drawn (per view, added up), Transforms uploaded, Materials uploaded, Entities, Animators / Animators posed, Bodies / Active bodies, Script instances.
- **GPU timer** (engine-private `Graphics/GpuTimer.*`): `Init` asks for `TimestampQuery` when the adapter has it (natively with Dawn's `timestamp_quantization` toggle off; browsers round to 0.1 ms unless chrome://flags has WebGPU Developer Features); every timed pass (`Renderpass::Start` given a label: the render graph's passes as "<graph name> <pass>" (`RenderGraph::SetName`: Scene, Game, Thumbnail, Player), the overlay as "UI") writes a begin/end timestamp into the frame's query set (3 slots of 128 passes; a frame whose slot isn't free isn't timed); `EndFrame` resolves them, copies them to a readback buffer and maps it, and the times reach `Profiler::SetGpuPasses` a few frames later (pass start relative to the frame's first pass). `Profiler::GpuStatus()` says whether and how passes are timed.
- **Game time** (`Mariana/Foundation/GameClock.hpp`): `GameClock` runs only in play mode (`Play`, `Pause`, `Stop`, `Step` = one 1/60 s frame while paused, `timeScale`, frames longer than 0.25 s count as 0.25 s); `DeltaTime()` is 0 unless the game runs, `Time()`/`Frame()` count from Play. Game systems step with `gameClock.DeltaTime()` (the animation system in both apps); the app's own things (editor camera, UI) use the real `OnUpdate` delta. The player calls `Play()` at the end of `OnStart`; the editor starts stopped.
- **Window**: GLFW, sRGB surface format preferred, Fifo present, resize callback, F11 fullscreen.
- **GUI** (editor only, owned by `EditorApp`): ImGui GLFW + WGPU backends, docking over viewport (`DockSpaceId()`, `CentralNodeId()`), windows move by their title bar only, custom "Mariana" style, JetBrainsMono Nerd Font. `EditorApp` inits it in `OnStart`, starts the frame in `OnGUI` and draws it with `Renderer::RenderOverlay` (the only thing on the screen).

### ECS (`Mariana/Scene/ECS.hpp`, `Prefab.hpp`)
Opaque wrapper over flecs; headers never include flecs.
- `Scene` (owns `flecs::world`), `Entity` (Scene* + uint64 id), `System` (flecs query + type-erased callback via `CreateSystem<Comps...>(fn(Entity, Comps&..., float dt), cascade)`: a cached query run manually with `.Run(delta)`; with `cascade` an extra optional LocalTRS term traversing ChildOf orders the tables by depth, so parents come before their children).
- Components must be registered by name: `ECS::RegisterComponent<T>("Name")` / `ECS::RegisterTag<T>("Name")` then `scene.UpdateComponentRegistry()`. `ECS::RegisterRuntimeComponent<T>("Name")` = one that only exists while something runs (what a system derives, what a simulation keeps on the entities it moves): queried like any other, never cloned by `Instantiate`, copied by `Snapshot`, put back by `Restore` or saved in scene files (`ECS::IsRuntimeComponent(name)`, also true for names starting with `_`; WorldXform, XformCache and TransformClock are runtime). Names matter — prefab cloning and the inspector look components up by name. The ECS's own components register themselves when a `Scene` is constructed (`ECS::RegisterBuiltinComponents`); modules provide `RegisterComponents()` for theirs (`Animator::`, `SceneRenderer::`), which the app calls.
- Built-ins: `NameComponent`, `LocalTRS` (pos, quat xyzw, scale, `version`), `WorldXform` (model[16], normal[9], `id`, `version`), `XformCache`, `TransformClock`. A flecs system (`cascade` on the parent term, so parents always update before children; the parent's WorldXform/XformCache arrive as query terms) recomputes `WorldXform` and bumps `WorldXform.version` when `LocalTRS.version` or the parent changes. Mutate via `SetPosition/SetRotationQuat/SetScale` (they bump the version only if the value changed), or write `LocalTRS` and `++version` yourself.
- Typed access (`Has/Get/TryGet/Add`) goes through `ECS::detail::TypeSlot<T>()`, a per-type index into `Scene::Impl::slot_ids`, so it never hashes `type_info`. System queries are cached (`EcsQueryCacheAuto`) and walk field arrays per table. `ForEachRoot` uses a cached `!ChildOf` query. `Scene::Each<T>(fn(entity, component))` visits every entity with a T through a query the scene keeps per component (uncached: one term goes straight to the tables with it, and a cached query would be an entity of its own, taking ids mid-session); `EntityCount()` (entities with a LocalTRS, counted by flecs) and `FindByName(name)` (smallest id wins).
- `WorldXform.id` is a per-scene monotonically increasing slot index into the GPU transform storage array.
- Hierarchy = flecs `ChildOf`. `Prefab` owns its own `Scene`; `Scene::Instantiate(prefab)` deep-clones by component name (skips runtime components). `Scene::Clear()` destroys every entity and restarts the transform slots at 0 (pair it with `SceneRenderer::InvalidateTransforms()`). `Scene::Snapshot()` copies every entity into a `SceneSnapshot` (its own Scene: components by name, no runtime ones, plus each entity's id, parent and transform slot, parents first); `Scene::Restore(snapshot)` detaches the snapshot's entities, destroys everything made since, brings destroyed ones back under their old ids (`ecs_make_alive`; a fresh id only if the index was taken), and resets each one's components, parent and transform slot (and the slot counter), so ids held elsewhere (selection, skin joints) stay valid. Pair it with `InvalidateTransforms` too.

### Rendering (`Mariana/Rendering/`, on top of the GPU wrappers in `Mariana/Graphics/`)
- `Renderer` owns `RenderGraph graph`; `Render(overlay)` executes the graph (whatever writes "Backbuffer" ends up on screen), then calls the optional `Renderer::Overlay` with a pass that loads the backbuffer and has no depth (the editor draws ImGui there). `RenderToTexture(target)` executes it into a render texture instead (offscreen: the editor's views, thumbnails); the static `RenderOverlay(overlay)` puts only the overlay on a cleared screen. Set the graph's backbuffer format and output size before adding passes that render to the screen.
- `RenderGraph` (`Rendering/RenderGraph.hpp`): named textures (`GraphTextureDesc`: format, `scale` of the output size or fixed `width`/`height`, `msaa`) and passes (`GraphPassDesc`: `colorTargets`, `resolveTargets`, `depthTarget`, `reads`, `keep`, `record(Renderpass&)`). `Compile()` orders passes topologically by what they read and write (insertion order otherwise; a later writer of a texture depends on earlier ones and loads instead of clearing), culls passes not needed for the backbuffer or a `keep` pass, creates every declared texture at its size (recreated on `SetOutputSize`), and calls the `OnTexturesChanged` callbacks after every compile so owners rebind. `SetFallback(name, tex)` = what readers get when nothing writes a name. Passes, textures and callbacks carry an owner; `RemoveOwner` removes a feature or effect. `AddPass` returns the pass's `Renderpass` immediately so shaders can be built against it; `Execute` recompiles when anything changed. Disabled passes (`Renderpass::SetEnabled(false)`) keep their previous contents.
- `Renderpass(msaa, depth, outputFormats, w, h)`: render graph passes get their textures through `SetTargets` (nullptr color = backbuffer) and `SetLoadOps`; standalone passes can still own targets (`Init`/`Recreate`). With `msaa` (`IsMSAA()`) the targets have 4 samples and resolve at the end of the pass into `GetRenderResloveTarget(i)` (the samples are discarded). Draws come from its `renderSystem` (an ECS System) and/or `recordCallback`, via `SetShader2(shader, variant = ShaderVariant::Default) / SetMesh / SetMaterial2 / Draw(indexCount, startIndex, firstInstance, instanceCount = 1)`. Redundant pipeline/mesh/material binds are skipped (switching only the variant keeps the bound groups); the shader's non-material groups are bound once per shader switch.
- `Shader2` builder: `.Group(i).AddBuffer/AddTexture/AddSampler(name, binding, ...)`, `.SetMaterialGroup(i)`, `.SetVertexStructLayout`, `.SetWGSL`, `.SetRenderpass`, `.Build(shadow)`. Pipeline hardcodes: entry points `vertexMain`/`fragmentMain`, front face CW, back-cull (none for shadow), depth LessEqual Depth24Plus, sample count from the renderpass (4 for MSAA passes, which also get the `AlphaToCoverage*` variants). `RebuildBindGroups()` recreates the shader's own groups after textures it reads were resized. Without `SetVertexStructLayout` the pipeline takes no vertex buffers and no culling (fullscreen passes; draw with `Renderpass::DrawFullscreen()`), and a renderpass without depth gets no depth state. `.SetDrawVariants(true)` also builds the other `ShaderVariant` pipelines on the same layout (`Renderpass.hpp`: `DoubleSided` = no culling, `Mirrored` = front-face culling for negative-determinant transforms, `Lines`, `Points`); `.SetDepthOnlyFragment(true)` keeps the fragment stage in a pass without color outputs (alpha-tested shadows). Samplers: `SamplerType_Repeat` (default; linear mag, nearest min, linear mips), `SamplerType_Comparison`, `SamplerType_LinearClamp` (linear everything, clamped). `BindTexture(name, tex)` re-points one of the shader's own texture bindings after Build (then `RebuildBindGroups()`).
- `Material2`: copies the shader's material bind group layout, `.SetTexture(name, tex)`, optional `.SetSampler(name, SamplerSettings)` (per-material address/filter/mip settings overriding the sampler's type), `.Build()`.
- `Buffer` + layouts (`UniformLayout.hpp`, `StorageBufferLayout.hpp`): layouts are built reflectively from a sample object + member refs and pack to WGSL alignment (vec3→16, mat columns stride 16). `StorageArrayLayout(count, obj, fields...)` for `array<T>`; `Buffer::Write(obj, index)`. Dynamic uniform buffers allocate stride*1024. `RawBufferLayout{size, type}` = a buffer packed by its user (written with `WriteRawBytes`), e.g. effect parameters.
- `VertexBufferLayout{v, v.field...}` builds the vertex layout from a struct. The standard renderer's vertex is `StandardVertex` (`Mariana/Geometry/Vertex.hpp`: position, normal, tangent, texcoord0/1, color0, boneIndices(uvec4), boneWeights).
- `StandardPBR.*`: `StandardPBRPipeline` = the scene's shared storage arrays (131072 elems) for transforms, materials and bones (transforms are staged with `QueueTransform` and sent by `FlushTransforms` in a few writes, runs of nearby slots); `StandardPBRView` = what each view has of its own: the UBO (lightDir, cascades, `sunColor`, `skySH[9]`, `skyParams`), camera UBO, draw data array and the shadow cascades' dynamic uniform.
- `Texture`: `TextureFormat` enum mirrors `wgpu::TextureFormat` values (cast directly). Load/Upload/Rescale (bilinear, CPU)/Cube/RenderTexture/Depth; `CreateTexture(..., mipLevels)` + `UploadTextureWithMips` (CPU box-filtered chain, any array layer); `CreateCubeTexture(faces, size, format)` uploads 6 faces with full mip chains (`LoadCubeTexture` loads files then calls it). `RequestPixelReadback(x,y)` / `TryGetPixelReadback(value)` = one async 1x1 readback in flight; `RequestImageReadback()` / `TryGetImageReadback(rgba)` = the same for all of mip 0 of an RGBA8 texture (rows padded to 256 bytes in the buffer, returned packed). `GetDisplayView(mip = -1)` = a view for showing the texture in a UI: sRGB textures are created with their UNORM sibling as a view format, so previews show the stored colors (cached per mip); `GetMipLevelCount()`.
- `IMesh`: `VertexCount()/IndexCount()` are what was uploaded; object-space `boundsMin/boundsMax` are computed by `BuildMesh` when the vertex has `.position`, plus `jointBounds` (bind-pose `Bounds` of the vertices each joint influences, indexed like `boneIndices`) when it also has bone indices/weights. `Submesh::topology` is `Triangles`, `Lines` or `Points`.
- Geometry (`Mariana/Geometry/`): meshes are built from `MeshSection`s (vertices, indices (empty = in order), `SourceTopology` incl. strips/fans/loops, `materialIndex`, `hasNormals`, `hasTangents`). `BuildMesh(sections)` converts each section to a list topology (`Geometry::ToListTopology`), gives triangle sections without normals flat normals (`GenerateFlatNormals`, de-indexed) and tangents where missing (`GenerateTangents`, Lengyel's method, w so the bitangent points up the texture as glTF expects), makes one submesh per section, uses 16-bit indices when <= 65536 vertices, uploads and frees the CPU arrays, keeping only the positions and the triangle submeshes' indices for physics (`IMesh::collision`, a shared `MeshCollisionData`; nullptr without triangles). It is `UploadMesh(PrepareMesh(sections))`: `PrepareMesh` is the CPU part (a `MeshData`: vertices, indices, submeshes; any thread), `UploadMesh` the GPU part. Both take a `MeshUsage` (`Mesh.hpp`): Static (default) frees the CPU data; KeepData keeps a copy as `IMesh::source` (the builtin primitives do, so a soft body can copy one); Dynamic keeps it too and makes the vertex buffer writable: `IMesh::WriteVertices(vertices, count, size, bounds)` replaces every vertex and the bounds and bumps `deformVersion` (part of a shadow caster's version, so its shadow is redrawn). Without a GPU device (the console test) a mesh gets no buffers, only its CPU side. `Primitives::Cube(size, subdivisions)/Plane/Sphere/Cylinder/Capsule` return sections (front faces outward, wound like glTF: the front is where cross(p1 - p0, p2 - p0) points); `BuiltinAssets::PrimitiveMesh(assets, BuiltinMesh::...)` shares built ones (`builtin://mesh/...`, kept on the CPU; `Grid` (a 1 m square in XZ, 24 x 24 cells) and `SubdividedCube` (8 x 8 cells a face) are for soft bodies). Importers and procedural code both go through this.
- The scene renderer is split in two. `SceneRenderer` (`Rendering/SceneRenderer.hpp`) = the scene's GPU data, shared by every view of it: transforms, material constants and bind groups, the skins' bones, the sky (cubemap, SH, mesh), `lighting` and settings. `RegisterComponents()` (MeshComponent, SkinComponent, ShadowCasterTag, CameraComponent and the runtime SkinPose; all but SkinComponent are in `Rendering/Components.hpp`) before `UpdateComponentRegistry`; `Init()` loads the sky and makes its systems; `Update()` once per frame (only when some view draws) uploads changed transforms and dirty material constants and poses the skins. `SetSettings(SceneRendererSettings)` changes `shadows`, `shadowDistance`, `shadowMapSize` and `sky` (the sky as background; off leaves SceneColor clear, alpha 0); the views apply it when they next prepare (a new size re-adds their maps; the graph recreates them and `BindGraphTextures` rebinds). `InvalidateShadows()` bumps an epoch every view compares. `SceneView` (`Rendering/SceneView.hpp`) = one camera's view of it in a render graph: `Init(graph)` adds its textures and passes, compiles and builds its shaders (`pbrShader` = test.wgsl, `skyboxShader`, `shadowShader`/`shadowMaskedShader` = shadow.wgsl, `prepassShader`; their group 0 binds the shared arrays and the view's own buffers); `Prepare(camera)` once per frame per view uploads its camera, lighting and cascades, builds material bind groups (`SceneRenderer::BuildMaterialBindGroups`: every material whose textures changed, against the view's `pbrShader` material group, which every view declares the same, so the first view to see a material builds it for all; empty slots get white sRGB / flat normal / white linear) and builds its draw lists. `CameraBuffer()` is what its effects read. Another view adds only its own camera, draws, shadow maps and graph textures. Graph textures: `ShadowMap0..3` (fixed `shadowMapSize`², Depth24Plus), `SceneDepth` + `SceneNormals` (RGB10A2, view space) + `EntityIds` (RGBA16Uint) from the "Prepass", `SceneColorMS`/`SceneDepthMS` (4x MSAA) resolved into `SceneColor` (RGBA16Float) by the "Forward" pass, which reads the shadow maps and `AmbientOcclusion` (R8, white 1x1 fallback when no effect writes it; test.wgsl clamps its `textureLoad`). The prepass is `keep` while the view's `writeEntityIds` (editor picking). The sky is an inward-facing `Primitives::Cube` drawn last with skybox.wgsl.
- Frame (inside `SceneView::Prepare`/`BuildDrawLists`): frustum-cull (mesh bounds vs camera/light frustum), sort by (variant, material, mesh, submesh), and turn each run into one instanced draw whose instances read consecutive `DrawData` entries (`frameDraws`, one write). Submeshes with a Blend material go to `blendedItems` instead: drawn one by one after the sky in the Forward pass, farthest first (by the distance of their bounds' center), with the `Blended`/`BlendedDoubleSided` pipelines (premultiplied alpha over what is there: src One, dst OneMinusSrcAlpha; depth tested, not written). Each draw picks a `ShaderVariant` (`DrawVariant()`: lines/points by topology, else `DoubleSided` for `MaterialAsset::doubleSided`, else `Mirrored` for a negative-determinant transform; alpha-tested materials use the `AlphaToCoverage*` variants). The prepass draws the same batches (not the blended ones).
- Shadows (per view): cascaded shadow maps (`kShadowCascades` = 4 maps, a constant in `StandardPBR.hpp`; size and distance from `SceneRendererSettings`, default 2048² out to 80 m). `UpdateShadowCascades()` splits the view (75% log / 25% uniform), fits each slice with a rotation-invariant sphere, snaps it to whole texels (no shimmering), and writes `UBO.cascadeVP/cascadeSplits/cascadeTexel` plus each cascade's matrix into the dynamic uniform `shadowCascadeBuffer` (`SetBufferIndex("ShadowCascade", c)` in the cascade's pass). Each cascade (graph pass "Shadow cascade c") culls casters against its own light volume and is skipped while its matrix and casters are unchanged (the light direction and alpha-tested materials' `Version()` are tracked, a cascade without casters ignores its matrix; `InvalidateShadows()` forces a redraw). With `shadows` off no casters are gathered, so the maps are cleared once and then skipped. Points, lines and blended surfaces cast no shadows. Casters are drawn whole (one index range, no fragment stage) except alpha-tested submeshes (material `alphaCutoff > 0`): those are drawn separately with `ShadowMapMaskedShader` (same `shadow.wgsl` plus a discarding fragment stage; its group 1 matches the PBR material group, so material bind groups are reused), and the opaque remainder of such a mesh is merged into contiguous index ranges. The shadow pipelines use slope-scaled depth bias (`Shader2::Build(true)`); receivers use a normal offset, 16-tap filtered PCF, blending between cascades, and a fade at the shadow distance.
- Skinning (GPU): glTF skins load as `Skin` assets (joint node indices + inverse bind matrices, `Mariana/Animation/Skin.hpp`); skinned nodes get `SkinComponent` (just the skin). `SceneRenderer::Update` gives each of them a runtime `SkinPose` (and takes it from one without a skin any more), whose joints are resolved by node index from the model's wrapper root (`ResolveJoints` in `SceneRenderer.cpp`). Each frame `SceneRenderer::Update`'s `skinningSystem` writes `inverse(meshWorld) * jointWorld * inverseBind` per joint into `frameBones` (one `boneBuffer` write; `BoneData` is just the matrix, normals use its 3x3) and sets `SkinPose::boneOffset`; draws carry it in `DrawData::boneOffset` (`~0u` = not skinned). It also moves each of the mesh's `jointBounds` by `jointWorld * inverseBind` into `SkinPose::bounds` (world space, exact for linear blend skinning), which the camera and every shadow cascade cull against (empty bounds = never culled). The pose version feeds the shadow cache. The skinned mesh node's own transform is effectively ignored, per the glTF spec.
- Cameras in the scene: `CameraComponent` (fov, near, far; `Rendering/Components.hpp`) on an entity that looks along its +z with +y up; `SceneCamera` (`Rendering/SceneCamera.hpp`, an `ICamera`) follows one (`Follow(world, camera)`, then `SetViewportSize` and `UpdateBuffer`).
- Lighting: `SceneRenderer::lighting` (`LightingSettings` in `StandardPBR.hpp`: sun azimuth/elevation/color/intensity, sky diffuse and reflection intensity, `skyRotation` = degrees the sky is turned around +y) is turned into the UBO each frame (a sun direction change redraws the shadows). The rotation (`UBO.skyParams.z`, radians) turns the sky's light, its reflections (`toSky()` in test.wgsl) and the drawn sky (skybox.wgsl reads the UBO at binding 3) together. `SceneRenderer::SkyDirection()` (`SkyBrightestDirection(sh)`) = where the sky's light comes from most, before the rotation; the default sky is brightest toward -z. The skybox cubemap is loaded in `Init` via `CreateCubeTexture` (mips for blurry reflections) and `ComputeSkyIrradianceSH` (`SkyLight.hpp`: L2 spherical harmonics of the sky, cosine-convolved and divided by pi) fills `ubo.skySH`. Each draw picks a `ShaderVariant` (`DrawVariant()`: lines/points by submesh topology, else `DoubleSided` for `MaterialAsset::doubleSided`, else `Mirrored` when the world transform's determinant is negative); draws sort by variant first.
- Effects (`Rendering/Effect.hpp`, files in `engine/resources/Effects/*.effect`, shaders in `engine/resources/Shaders/Effects/`): an effect file (JSON) declares `stage` ("BeforeLighting" writes scene textures the forward pass reads, e.g. GTAO writes `AmbientOcclusion`; "PostProcess" runs on the HDR image), `final` (writes the screen, always last: Tonemap), `parameters` (float/int/bool/vec2-4/color3-4 with default/min/max, packed in file order with WGSL layout into a uniform `params`), private `textures` (format, scale or size) and `passes` (shader, `inputs` binding name -> texture, `output`, per-pass `constants`). Names are private textures, `Input`/`Output` (the post chain) or any graph texture. Each pass shader only defines `fragmentMain(input: FullscreenInput)`; the effect system prepends `params`, `passInfo` (outputSize xy/zw, constants), `camera` (CameraInfo), `linearClamp`, the inputs (depth formats as `texture_depth_2d`) and the fullscreen vertex shader. `EffectStack` (one per view, owned by the app) loads effects (`Add(path)`, or `Add(definition)` to reuse a loaded one), removes, moves within a stage, and rebuilds its part of the graph when effects are added, removed, moved or toggled (pipelines are kept when formats don't change); post effects chain through `PostColor<i>` textures from `SceneColor` to the backbuffer, and `Present.effect` is used when no final effect is enabled. Exposure is the camera's (`ICamera::SetExposure`), read by tonemap.wgsl and skybox.wgsl.
- Render pipelines as data (`Rendering/RenderPipeline.hpp`, files in `Pipelines/*.pipeline` under any root, the default in `engine/resources/Pipelines/`): `RenderPipelineDesc` = name, `exposure`, `scene` (`SceneRendererSettings`) and `effects` (effect file path, `enabled`, parameter values by name). `Load(path, desc, error)` / `Save(path, error)` (JSON, see the header; missing values keep defaults, unknown parameters warn on Apply), `Apply(effects, sceneRenderer, camera*)` (clears the stack and loads every effect file anew), `Capture(effects, sceneRenderer, camera*)` = what runs now. It is plain data, so code (and later scripts) can build, edit and apply one; custom shaders and bindings come in through effect files.

- Importers (`Mariana/Importers/`, engine side): `GLTF::GLTFLoader::RegisterLoader(assets)` makes it the `AssetManager2` loader for `.gltf/.glb` (`assets.Load<Prefab>(path)`); it needs no renderer. Accessors: `ReadAccessor<T>` handles strides, normalized integers, sparse substitutions and accessors without a buffer view (zeros); `ReadAccessor<glm::mat4>` reads inverse bind matrices. Loading is two halves: `GLTFLoader::Parse(file, error, ParseOptions{maxImageSize})` (any thread, touches no GPU or shared state: tinygltf, images to RGBA8 (shrunk as they are decoded when `maxImageSize` is set), every mesh's `MeshData`; warnings collected) returns a `ParsedGLTF`, and `LoadGLTF(assets, parsed)` (main thread) makes the assets and the prefab and logs the warnings; `LoadGLTF(assets, file)` does both. `Dependencies(parsed)` = the files its content comes from (external buffers and images, and the `.material` files its materials are or would be extracted to). ### Physics (`physics/` → MarianaPhysics, on Jolt Physics)
- Jolt stays private: public headers use glm and engine types only. `JoltCommon.hpp`: glm/Jolt conversions; layers (object layer = `(user layer << 1) | moving`, broad phase Static/Moving, a pair filter from the settings' matrix; two static bodies never collide); `ColliderMaterial` (a `PhysicsMaterial` carrying each collider's friction and restitution on its sub-shape; contacts combine friction by the geometric mean and restitution by the max; a soft body has no sub-shapes, so its own are used, and Jolt asks for what is near a soft body with an empty sub-shape id, which a body of several colliders can't look up (the index would be past the end: a crash on the web), so that gets the body's own, its first collider's: `ContactMaterial`). Jolt's trace and asserts go to the Logger.
- Components (`Mariana/Physics/Components.hpp`; `PhysicsWorld::RegisterComponents()`: "RigidBody", "BoxCollider", "SphereCollider", "CapsuleCollider", "CylinderCollider", "MeshCollider", and "Joint", "Vehicle", "VehicleWheel", "CharacterController"): `RigidBody` (`motion` Static/Kinematic/Dynamic, `mass` (0 = the colliders' volume times density), damping, `gravityFactor`, `continuous` (Jolt LinearCast), `allowSleeping`, `lockedAxes` (`LockedAxis` bits, world space; all six make it kinematic), `layer`, start velocities). Colliders derive from `Collider` (center, rotation, friction, restitution, density, `isTrigger`): box `size`, sphere `radius`, capsule and cylinder `radius` + `height` along local Y (the capsule's tip to tip), `MeshCollider` (`mesh`, empty = the entity's MeshComponent mesh; `convex` = its convex hull; a triangle mesh on a dynamic body is used as its hull, with a warning; scaled in the mesh's own axes, then turned by the collider's rotation). Unity's rules: a RigidBody's body is its colliders plus its descendants' down to the next RigidBody (a StaticCompound; a single offset collider is a RotatedTranslated shape); colliders with no RigidBody on or above them are a static body of their own; scale scales the shapes (boxes per axis, round shapes by the larger radial scale). Triggers are sensors that also notice static and kinematic bodies; a body with solid colliders and triggers gets a second, kinematic sensor body that follows it. `ColliderGeometry.hpp`: `ForEachCollider(entity, transform, fn)` = the shapes as placed (also what the editor draws; meshes carry their `MeshCollisionData`, bounds and scale), `HasCollider`, `ColliderMesh`, `MeshBounds(entity)` (its mesh's bounds, or for a model's root those of the meshes below it) and `FitColliders(entity)` (box/sphere/capsule/cylinder to those bounds; a flat mesh gets a 0.1 thick slab under its surface). `Shapes.cpp` (private) makes the Jolt shapes; `ShapeCache` keeps triangle meshes (`MeshShape`, vertices welded by position so seams aren't open edges) and convex hulls per mesh and surface, unscaled (a `ScaledShape` scales them), for as long as the mesh lives, so Play after Play reuses them (Sponza's takes ~0.35 s on the web the first time). The world's code is split over `WorldImpl.hpp` (the `Impl`), `PhysicsWorld.cpp` (sync, steps, contacts), `Queries.cpp` and `DebugDraw.cpp`.
- `PhysicsWorld` (`Mariana/Physics/PhysicsWorld.hpp`, one per scene, owned by the app): a Jolt `PhysicsSystem` (65536 bodies), 16 MB temp allocator, `JobSystemThreadPool` natively / `JobSystemSingleThreaded` on the web. `Step(dt)` with game time: first `Sync` (finds the entities with RigidBody, collider and the features' components through cached queries (`Find<T...>()` over `Scene::Each`: each once, in entity id order) instead of walking the scene, and places them from the root down (`NodeOf`, memoized per sync, the transform system's order of multiplication, so a still body stays exactly where it is; on or below a wheel or a character nothing is a body); a collider goes on the nearest RigidBody on or above it, colliders in entity id order; bodies made in entity id order; a body is made again when its signature changes, an FNV hash of its RigidBody and collider geometry, keeping a dynamic body's velocity; bodies whose entity or components went are removed; a static body moved by the editor or code is moved, a dynamic one whose `LocalTRS.version` isn't the one it wrote is teleported), then fixed steps (`fixedTimestep`; an accumulator with a 1e-6 tolerance so a Step button frame is exactly one step; at most `maxStepsPerFrame`, then time is dropped): kinematic bodies `MoveKinematic` to their entity, Jolt `Update`, and `TrackPoses` keeps where each dynamic body, ragdoll bone, character and soft body was after the last two steps. Then every Step call (also one that ran no step) shows them (`Show(alpha)`), through ECS systems over runtime components the world puts on the entities it moves (`WorldImpl.hpp`; registered by `RegisterComponents`): `PhysicsBody` (on a dynamic body's, a character's or a ragdoll bone's entity: the body it follows, the last two poses (filled after each step by the `trackBodies` system, or by `TrackCharacters`), the shown pose, the written version, `show`) is written by the `showBodies` system (cascade: parents first, so a body below another is put under its new pose) into `LocalTRS` (in the parent's space; `++version` only when it changed), so rendering and children follow as with animation; `PhysicsWheel` (chassis, wheel index) by `showWheels`; `PhysicsSoftBody` (the drawn copy of the mesh and how it is made from the particles) by `trackSoftBodies`/`showSoftBodies`. The world keeps what makes them move (Jolt's bodies and objects, in its records), so it can take that away when an entity or its components go, and adds and removes the components (adds after the candidates loop: adding one moves an entity's components, which the candidates point at). With `PhysicsSettings::interpolation` (and `RigidBody::interpolate`) they are shown between the last two steps by `accumulator / fixedTimestep` (smooth on any frame rate, one step behind), else where the last step left them; wheels are placed on the chassis as shown. `ShowLatest()` writes the latest poses (the editor calls it while paused, so Step shows its step). Bodies belong to the world (entity id -> record), not to components, so copies (prefab instances, snapshots) get their own (the runtime components aren't copied). `Reset()` drops every body and makes a new `PhysicsSystem`: the same scene then simulates exactly the same way each time (two Play runs match pixel for pixel). `GetBodyInfo(entity, info)` (motion, sleeping, sensor, mass, velocities), `BodyCount()`, `ActiveBodyCount()`.
- Queries (`Queries.hpp` types; against the bodies as the last Step left them): `Raycast` / `RaycastAll` (nearest first, once per body) / `ShapeCast` (`QueryShape::Sphere/Box/Capsule`, turned; a shape already touching something hits it at 0) give `RaycastHit` (entity, point, normal, distance); `Overlap` the entities a shape touches (sorted by id). `QueryFilter`: a layer bit mask, `triggers` (off by default), one entity to `ignore`. Forces on dynamic bodies (false without a dynamic RigidBody): `AddForce`/`AddForceAtPoint`/`AddTorque` act through every fixed step of the next Step call (call them each frame for a steady push; queued even before the body exists), `AddImpulse`/`AddImpulseAtPoint`/`AddAngularImpulse` once; `SetVelocity`/`GetVelocity`, `Teleport` (entity and body at once, so queries see it), `WakeUp`. Checked: an impulse of 10 N s on 2 kg gives exactly 5 m/s, 1 s of 20 N exactly 10 m/s.
- Contact events: `Events()` = the `ContactEvent`s (Begin/End, entities `a` and `b` with the trigger as `a`, `trigger`; on Begin the point, normal from a to b and approach `speed`) of the last Step call, once per pair of bodies however many sub-shapes touch, sorted so threads don't change their order; `IsTouching(a, b)`. Jolt reports per sub-shape pair from its worker threads (`ContactCollector`, locked) and also drops a body's contacts when it falls asleep; those are kept as asleep and only end if the bodies have been awake two steps without the contact coming back, so a body resting in a trigger never "leaves" it by sleeping. Contacts of removed bodies end in the next step.
- Debug view: `DebugDraw(PhysicsDebugDraw, lines)` appends `DebugLine`s (RGBA8, red low byte, as ImGui's) from Jolt's `DrawBodies` through one process-wide `DebugRendererSimple` (shapes in wireframe coloured by motion type or awake/asleep, bounding boxes, centers of mass, velocities; round shapes' detail from `cameraPosition`; at most `maxLines`), plus the contact manifolds Jolt drew during the steps since `contacts` was asked for (`ContactConstraintManager::sDrawContactManifolds` only while stepping). - Vehicles (`Mariana/Physics/Vehicle.hpp`, `Vehicles.cpp`; Jolt's `VehicleConstraint`): a `Vehicle` on an entity with a dynamic RigidBody (the chassis; its colliders are the body; `RigidBody::centerOfMass` lowers it) and a `VehicleWheel` on each wheel entity below it (not below another body). The chassis drives along +Z, +Y up, +X right; Jolt's right is -X, so steering is passed negated and Jolt's left track/differential side is +X. - Characters (`Mariana/Physics/Character.hpp`, `Characters.cpp`; Jolt's `CharacterVirtual`): a `CharacterController` (radius, height, max slope, step height, stick-down distance, mass and strength for pushing, walk speed, run factor, jump speed, gravity factor, air control, turn to move at `turnSpeed`, layer; driven by `move` (world, horizontal, length <= 1), `run`, `jump`) on an entity without a RigidBody makes a capsule standing on the entity's origin (a RotatedTranslated capsule, the supporting volume its bottom sphere) with a kinematic inner body moving with it (so queries hit it and bodies bump into it; it is in `bodyEntities`) and character-vs-character collision (`CharacterVsCharacterCollisionSimple`). `SyncCharacters` (end of `Sync`) makes it, makes it again (keeping its velocity) when its shape, slope, mass, strength or layer change, and puts it where its entity is when someone else moved the entity (LocalTRS version); colliders on or below a character take no part (`Collect` stops there). `MoveCharacters` before each step does what Jolt's sample does: on the ground going with the ground's velocity plus the walk (and the jump), in the air keeping its velocity steered by `airControl`, plus gravity, turning about +Y toward the walk, then `ExtendedUpdate` (move, walk up stairs, stick to the floor); the write-back puts the entity at the character's feet with its yaw (its `PhysicsBody`, filled by `TrackCharacters`), and `SpendJumps` spends the jump after a Step call's steps. - Joints (`Mariana/Physics/Joint.hpp`, `Joints.cpp`; Jolt's two-body constraints): a `Joint` on an entity holds the body at or above it (the nearest RigidBody on it or an ancestor, else its own static body) to the `connected` entity's (by name, the smallest id when names repeat; the body at or above it; empty = the world; `toParent` = the body above its own, for nested bodies like chains and ragdolls). Types: Fixed, Point, Distance (`connectedAnchor` on the connected entity or a world point, min/max distance (< 0 = at the start), spring), Hinge and Slider (limits in deg / m with an optional spring, a velocity or position motor with `motorStrength` and `motorFrequency`, friction), Cone, SwingTwist (swing half angle, twist range) and SixDOF (`lockedAxes` held, the rest free). `SyncJoints` (end of `Sync`) makes them in world space from the poses then, with the connected body (or the world) as Jolt's body 1, so angles, positions and motors are the joint's own body relative to what it holds on to; it makes one again when the joint's settings (not its motor, friction or break limits, set every step by `DriveJoints`), its place on its body (the LocalTRS chain, never world matrices) or the bodies change; `DropJointsOf(body)` runs before any body is removed or made again (a constraint must not outlive its bodies). Unless `collideConnected`, the two bodies get collision groups carrying their body index and a `JointCollisionFilter` keeps the pair apart. `CheckJoints` after each step reads the position and rotation impulses (/ dt = N, N m; `GetJointInfo`: active, broken, force, torque, hinge angle / slider position / distance length) and breaks those past `breakForce` / `breakTorque` (marks its record broken (`JointInfo::broken`; not made again, even when its bodies are, until Reset); `BrokenJoints()` = those of the last Step call). Checked on stepped time: a 2 m pendulum swinging 10 deg has a period of 2.844 s (2pi sqrt(L/g) with the bob's inertia and the amplitude: 2.844), a hinge motor turns at its 180 deg/s, a slider stops at its 1 m limit, a ball joint holds a 2 kg box with 19.62 N and breaks (limit 30 N) the step 20 N more pulls, a 10-link chain hangs straight to 1.24 m (1.25), a door stops at 103 deg against its 100 deg limit, the wrecking ball scatters its crates.
- Water (`Mariana/Physics/Water.hpp`, `Water.cpp`): a `WaterVolume` (box `size` centred on its entity, top face the surface; `density` 1000, Jolt's quadratic `linearDrag`/`angularDrag`, `damping` (1/s times how far under: settles what floats, which the quadratic drag barely does at low speed), `flow`, waves (`waveHeight`, `waveLength`, `waveSpeed`: two crossing sines, `WaterSurfaceAt` gives the surface point and normal under a point), `rippleSpeed`). `Collect` gathers the volumes (`WaterRecord`s: center, axes, half size, still top, world bounds); before each fixed step `ApplyBuoyancy` (bodies in entity order) takes each dynamic body whose bounds meet a volume and whose center is within its sides, asks Jolt for its submerged volume under the surface there and applies `Body::ApplyBuoyancyImpulse` with buoyancy = water density x shape volume / mass x `RigidBody::buoyancy` (Jolt's factor is the fluid's density over the body's), then the damping (relative to the flow); a sleeping body in still water is left asleep. - Ragdolls (`Mariana/Physics/Ragdoll.hpp`, `Ragdolls.cpp`; Jolt's `Ragdoll`): a `Ragdoll` on a model's root (the entity with the Animator) makes a ragdoll of its skeleton when the simulation starts. `PlanRagdoll(scene, root)` (also what the editor shows before Play) picks the bones by name (Mixamo's and common ones: hips/pelvis, spine, neck, head, upper and lower arms, hands, thighs, shins, feet; fingers, toes, twist, clavicle, end bones and the like are left out and follow their parent), each joined to the nearest picked bone above it, in the skin's bind pose (`meshWorld * inverse(inverseBind)`): a capsule from the bone to its picked child (leaves, along their skin bounds), the radius from the mesh's `jointBounds`, the hips a capsule across between the thighs (Rumba: 18 bodies). `mass` (80 kg) is shared by volume; knees and elbows are hinges bending their way (back / forward of the model's +Z), the rest swing twist joints with limits by kind (`RagdollJointKind`), times `jointLimitScale`. Its bodies never collide with each other (its `GroupFilterTable`), get 30 velocity / 6 position solver steps, and constraints are solved from the hips out (`CalculateConstraintPriorities`). Modes (`RagdollMode`): Animated = kinematic bodies on the animated pose (`DriveToPoseUsingKinematics`: they push things, nothing moves them); Powered = dynamic bodies without gravity whose joint motors (15 Hz, critically damped, torque up to `strength`) drive toward the animated pose with the pose's motion fed forward (`DriveToPoseUsingMotors(previous, pose, dt)`), the hips moved to the animation's (`MoveKinematic`), so it dances like the animation (spine and head within a few cm, fast hands and feet up to ~0.2 m behind) and can be knocked about; Limp = gravity, no drive. - Soft bodies (`Mariana/Physics/SoftBody.hpp`, `SoftBodies.cpp`; Jolt's soft bodies): a `SoftBody` on an entity with a MeshComponent deforms its mesh. `SyncSoftBodies` (end of `Sync`) makes it from the mesh's `source` data (a mesh not kept on the CPU is copied from its collision triangles, without texture coordinates, with a warning): vertices within 0.1 mm of each other become one particle, triangle submeshes its faces (`CreateConstraints`: edges, shear edges across quads, distance bend constraints when `bendStiffness` > 0, and with pins Euclidean long range attachments; then `Optimize`), placed in world space around their bounds' center, sharing `mass` (pinned ones kinematic). `stiffness` and `bendStiffness` (0..1) become XPBD compliance relative to the particles' inertia per sub-step (10 (1 - s)^3 (w1 + w2) dt^2) and `pressure` is a push of that many of its weights over its surface at rest (Jolt's n R T = pressure m g V0 / A), so they mean the same for any mass, size or resolution (an absolute pressure on a light mesh is more than the position solver can hold). Faces are flipped for Jolt when the mesh is inside out (pressure pushes along their normals); `closed` = every edge between two faces. It is made again when its settings (not pressure or wind) or its mesh change. The entity draws a copy of the mesh instead of its own: a runtime `MeshOverride` (engine, `Rendering/Components.hpp`: what the views draw instead of the MeshComponent's mesh, with its materials) holding `UploadMesh(..., MeshUsage::Dynamic)` (registered without a key), with the particle mapping in its `PhysicsSoftBody`; the MeshComponent is never touched. The `showSoftBodies` system writes the copy every frame it moves: the particles interpolated between the last two steps, in the entity's space, each vertex's normal from the particle faces around it within 60 deg of how it was modelled (smooth across UV seams, creases kept), tangents regenerated, the bounds; asleep, it isn't written. Removing it (or Reset) takes the override away, so the entity draws its own mesh again. `pin` (`SoftBodyPin`: a side of the mesh's bounds in its own axes, so a plane primitive's edges are Left/Right/Front/Back, or the Corners or TopCorners of its two widest axes) makes those particles kinematic: `DriveSoftBodies` before each step sets their velocity to reach where the entity has them, and blows `wind` (world m/s; `gusts` vary its strength and direction and run ripples down it) on each face by how squarely it meets it (0.6 A (n.v)|n.v| plus a little drag along it), waking the body. It collides with rigid bodies (a character's inner body pushes it too; a vehicle's wheels pass through it, its chassis doesn't); it makes no contact events and doesn't float. `GetSoftBodyInfo` (particles, faces, springs, attachments, pinned, closed, volume and rest volume, touching, awake, world bounds). ### Scripting (`scripting/` → MarianaScripting, on Luau)
- Luau stays private: public headers use engine types only. `Script.hpp`: `ScriptAsset` (asset type `Script`, `.luau`/`.lua` through `ScriptAsset::RegisterLoader`: `source`, `bytecode` compiled with `vec3` as the vector constructor, compile `error`, `file`; `SetSource(text)` recompiles and bumps `Version()`; `ReloadIfChanged()` reads the file again when its write time changed) and the component `Scripts` (`scripts`: `ScriptSlot` = the script handle, `enabled`, `values` = `ScriptValue`s (name, Number/Bool/String/Vector) set on this entity; the other properties are the script's defaults). Saved with scenes (`Serializers.cpp`; the script by reference, so it is a dependency the player packages).
- A script is a module returning a table: its functions (`Start`, `Update(dt)`, `LateUpdate(dt)`, `OnDestroy`, `OnContactBegin(other, contact)`, `OnContactEnd`, `OnTriggerEnter/Exit(other)`) run per entity with a `self` of its own (`self.entity`), and its `properties` table names the values the inspector edits, with their defaults (put into `self` before Start). `scripting/API.md` is the script API.
- `ScriptWorld` (`ScriptWorld.hpp`, one per scene, owned by the app like PhysicsWorld; `SetPhysics`, `SetTimeLimit`): one Luau state (`State.cpp` `NewState`: `luaL_openlibs`, print/warn to the Logger, the bindings, then `luaL_sandbox`; the native code generator when supported), made when there is a script to run. `Update(dt, input*)` first syncs: the scripted entities by `Scene::Each<Scripts>` in id order; modules first (a module = the chunk run in a sandboxed thread of its own; its table, a shared metatable whose `__index` is the table, refs to its callbacks), then the instances (records keyed by entity id and slot, sorted; new ones get `self` with the properties, gone ones end with OnDestroy; values edited in the inspector while playing are put into `self` property by property); then every new instance's Start, then Update; destroys asked for are done after (`FlushDestroys`: OnDestroy for the scripts on the entity and below it, then `Scene::Destroy`). `LateUpdate(dt)` hands the physics events of the last Step to both sides (the normal pointing from each to the other), then the animation events of each scripted entity's Animator (`OnAnimationEvent(self, name, clip)`, instances in entity id order), then LateUpdate. Scripts compile with `time` as a mutable global (`ScriptAsset.cpp`): Luau otherwise resolves `time.time` once at load (an import) and keeps it. `Reset()` (Play, Stop, ClearScene) calls OnDestroy and closes the state. Calls are protected (`lua_pcall` with a traceback); an error stops that instance (`GetError(entity, slot)`, logged) until its script changes; the interrupt callback stops a call running past the time limit (2 s; the clock read every 1024 interrupts). `ReloadChanged()` (at most twice a second) re-reads changed script files: a module loaded again swaps its metatable's `__index`, so every instance runs the new code and keeps its state (failed ones start again; properties new in it are added); a reload that doesn't compile keeps the old code. `Describe(script)` = its properties with defaults (sorted by name) and error, from a second state without the game's libraries, cached per version.
- Bindings (`Bindings.hpp`): `Context` (scene, assets, clock, physics, input, pending destroys, the call deadline) behind `lua_callbacks(L)->userdata`; tagged userdata with fixed metatables (`kEntityTag`: the id; `kComponentTag`: entity id + serializer; `kQuatTag`: a glm::quat; `kTimeTag`); names as atoms (`useratom`, `Atom` enum) so `__index`/`__namecall` switch on a number. Entities are cached in a weak table by id, so one entity is one value (table keys work). `MathBindings.cpp`: `vec3` and `quat`; `EntityBindings.cpp`: Entity (transform through the LocalTRS chain, current before `Scene::Update`; setters through `SetPosition`/`SetRotationQuat`/`SetScale`, so versions bump) and Component: fields read and written through the component's scene file visit function over a `FieldVisitor` (`FieldReader`, `FieldWriter`, `TableWriter` for `Add(name, fields)`; 2/3 floats are vectors, enums by name), an unknown field an error, and the Animator's methods; `GameBindings.cpp`: `scene`, `input` (keys by name), `time` and `physics` (PhysicsWorld's queries, forces, velocities, teleport, infos, ragdoll mode, water).
- Editor (`Editor/Scripting/ScriptEditor.hpp`): the inspector's Scripts section (per script: enabled, name, Open (the system's app, natively), Remove, its compile or run error, its properties with the entity's own values in the check-mark colour (right-click: reset to default); Add Script: a new file from the template in `<project>/Scripts/`, or one of the project's scripts; drop a `.luau` from Assets (`MARIANA_ASSET_SCRIPT`)), Add Component > Scripting > Scripts; edits are undo steps (`InspectorComponents::EditComponent` and `Section` in `ComponentEdit.hpp`, shared with the physics UI). Assets: right-click > Script makes `NewScript.luau` from the template, double-click opens a script in the Script Editor (the inspector's Open button opens it with the system's app, natively). `EditorApp` owns `scripts`; `Update` runs on the frames the game moves (playing, or a Step while paused) with the keys unless a text field or the camera fly has them, `LateUpdate` after the follow cameras, `ReloadChanged` every frame; Play and Stop `Reset` it (Stop before the scene is restored).
- Types (`scripting/tools/`, MarianaScriptTools): `ScriptTypes::Definitions()` = the hand-written core `scripting/tools/resources/Core.d.luau` (the path is the compile definition `MARIANA_SCRIPT_TOOLS_RESOURCES`; the editor's web build preloads the folder) (vec3, quat, Component, AnimatorMethods, Entity, `Script` = `{ entity: Entity, properties?, [string]: any }`, Contact, RaycastHit, the scene / input / time / physics libraries) with, where its `-- @components` and `-- @componentMethods` lines are, a `declare extern type` per registered component (its fields read by running its scene file function over a default one with a describing `FieldVisitor`: numbers, booleans, strings, enums as unions of their names (`FieldVisitor::Value::names`), 2 or 3 floats as vector, quat, lists; Animator extends AnimatorMethods), `export type ComponentName` and `Entity:Get/Add` overloads per component name (`SceneFile::ForEachComponent`). `ScriptChecker` = a `Luau::Frontend` (the old solver, as luau-lsp's default; nonstrict unless `--!strict`) over the scripts' current text with the definitions in both its globals and the autocomplete ones: `Check(name, source)` → `ScriptDiagnostic`s (lines/columns from 0, syntax or type), `Complete(name, source, line, column)` → `ScriptCompletion`s (methods / properties / variables / keywords / strings; fields after ':' dropped; inside a string only the strings, unquoted). Scripts are written `local X = {} :: Script` with `function X.Update(self: Script, dt: number)`: `function X:Update` runs the same but its body isn't checked (neither solver types `self` from a table with an indexer). The editor makes one `ScriptChecker` after the components are registered (`EditorApp::scriptChecker`), shows a script's type problems in the inspector (count + first three, cached per script version) and natively writes `<project>/.mariana/types/Mariana.d.luau` (when it changed) and, if missing, `<project>/.vscode/settings.json` for the Luau Language Server (`ScriptEditor::WriteProjectTypes`).
- Script Editor (`Editor/Windows/ScriptEditorWindow.*`, Window menu; opened by double-clicking a `.luau` in Assets and by a script's Edit button in the inspector): a tab per script (unsaved marker), the text in an `ImGui::InputTextMultiline` as big as its text inside a scrolling child (so the line-number gutter, the colours and the underlines share its scroll), drawn with transparent text and frame over the colours drawn from `ScriptTokens` (`ScriptTools/ScriptTokens.hpp`: Luau's own lexer; keywords, library names, numbers, strings, comments), ImGui's caret and selection on top. The checker runs 0.3 s after typing stops: problems are zigzag-underlined (hover says what), counted in the toolbar and listed under the text (click goes there: `GoTo`). Completions come after `.`, `:` and `"` (the text field's char filter asks) or Ctrl+Space, narrowed by what is typed since; Up / Down pick (the caret is put back), Enter / Tab take (filtered out of the text, inserted by the field's callback), Esc closes (the key is owned so the field doesn't revert its edit). Ctrl+S (a focused route, so the scene's global Ctrl+S doesn't fire) writes the file and `ScriptAsset::SetSource`s it, so the running game reloads it; `onSaved` hands it to the browser on the web. A tab without unsaved typing follows its script when it changes elsewhere.
- The game controls are the Sandbox's scripts, not the engine's: nothing scripted ships with the engine or MarianaScripting. `projects/Sandbox/Scripts/` has `VehicleDriver.luau`, `CharacterDriver.luau` and `ChaseCamera.luau` (the keys driving a `Vehicle` / walking a `CharacterController`, a chase camera; `scripting/API.md`), which the editor's Create menu, `BuildStartupScene` and the player's presets put on what they make by resource path (`ScriptWorld::AddScript`, `/Scripts/...`, found in the project: a project without them gets an error in the log and an undriven vehicle; it copies them from the Sandbox), `Respawn.luau` (on the car: R puts it back at the start, at rest), `LaunchPad.luau` (on the "Launch Pad" at (-10, 0, 20): a trigger that throws what enters it up at 11 m/s and on along its +Z) and `Hover.luau` (its marker cube bobs and turns), `WatchCar.luau` (on each dancer: sets its graph's `lookTarget` to the driven car (the first entity with a VehicleDriver, or `target` by name) and eases `lookWeight` toward 1 within `range` (25 m), so the dancers turn their heads to watch it coming; their powered ragdolls follow the turned pose).

### Building games (`export/` → MarianaExport)
- `BuildProfile` (`Mariana/Export/BuildProfile.hpp`): name, platform (Windows / Web), configuration (Release / Debug), output folder (relative to the project; empty = `Builds/<name>`), game name (the exe's), window title / size / icon, the start scene and more scenes to package, a pipeline (empty = the scene's), follow camera, log frame times, whole project. `BuildProfiles` (`profiles`, `active`) = a project's `BuildProfiles.json` (format in the header; `Defaults`: Windows and Web starting in its first scene, Playground's if it has one); the Sandbox has Windows and Web, Release, in Playground.scene.
- `GameExport` (`GameFiles.hpp`): `CollectFiles(project, profile)` = what the game takes, relative to the project (the scenes and their dependencies, a `.gltf`'s folder, a `.glb`'s `.materials` folder, Physics.json, the pipeline and icon when they are the project's, the Scripts folder; with `wholeProject` everything but `.mariana`, `Builds`, `.vscode`, `.git`; warnings for dependencies that are nowhere); `PlayerConfig(project, profile)` = the project's Player.json with the profile's window, scene, pipeline, `camera.follow` and `profile` over it; `StageFiles` copies them (without editor caches) and writes it.
- `Process` (`Process.hpp`, Windows; elsewhere an error): `Run(args, options, line)` (stdout and stderr by line, extra environment, a cancel flag; in a job object, so cancelling or finishing ends what it started), `Background` (a server until `Stop`), `Launch` (a game on its own, detached), `FindOnPath`.
- `BuildTools` (`GameExporter.hpp`): the engine source, CMake, the native build folder (where the editor was built), the web build folders (`build-web-release` / `build-web`), the Emscripten SDK (`EMSDK`), from compile definitions or the project's `.mariana/build-tools.json` (this machine's); `Missing(platform)`; `WebEnvironment` (EMSDK, EM_CONFIG, the SDK's Python on PATH).
- `GameExporter(project, profile, tools)`: `Start` (a thread; the editor) or `Run` (the CLI), `Cancel`, `Step`/`Progress`/`TakeLines`/`onLine`. Windows: `cmake --build <native> --config <c> --target MarianaPlayer` (MSBuild node reuse off), then `<output>/<game>.exe`, `data/engine` (the engine's resources), `data/game` (the staged files) and `<game>.exe --check`. Web: `emcmake cmake -G Ninja` the first time, `cmake --build <web> --target MarianaPlayerRuntime`, its `index.html/.js/.wasm/.data` into the output, the staged files packed by Emscripten's `file_packager.py` into `game.data` + `game.data.js` (mounted at `/game`). `GameRunner` starts the exe, or serves the web build with Emscripten's `emrun` on `http://localhost:6931/index.html` (it opens the browser) until stopped.

### Assets (`Mariana/Assets/`)
- `AssetManager2` is owned by `Application` (`assets` member, declared in the base so it outlives the scene). Per-type `AssetStorage<T>` of `shared_ptr<T>`; `AssetMetadata` per UUID `AssetID` (name, type, `path` = reloadable file, `key` = unique lookup key, `source` = the file its data is in when that isn't `path` (an image, a saved .material; `RegisterAsset(..., source)`, `SetSource`), status, refCount, persistent).
- `AssetHandle<T>` is ref-counted and caches the asset (`Get()` returns `const std::shared_ptr<T>&`, no lookup; `Manager()` is the manager it belongs to); components hold handles (`MeshComponent`, `Animator`, a `MaterialAsset`'s texture slots). Include `Mariana/Assets/AssetManager.hpp` (not just `AssetHandle.hpp`) wherever handles are copied or resolved.
- API: `RegisterLoader<T>(type, exts, fn)`, `Load<T>(path)` (dedupes by key), `LoadAsset<T>(id)`, `RegisterAsset<T>(ptr, type, name, key)` for in-memory/sub-assets, `Find<T>(key)`, `ForEach<T>`, `UnloadUnused()` (cascades until stable), `SetPersistent`.
- Asset types in use: `Texture`, `IMesh`, `Skin`, `Skeleton`, `MaterialAsset`, `AnimationClip`, `AnimationGraph`, `Prefab`.
- `MaterialAsset` (`Mariana/Rendering/MaterialAsset.hpp`) is source-independent (importers, code, the editor make them the same way): `properties` (`PBRMaterialProperties`, mirrors `MaterialProperties` in the shaders; call `MarkDirty()` after changing it), `doubleSided`, `SetAlphaMode(Opaque/Mask/Blend, cutoff)` (writes `alphaCutoff` for Mask and `alphaBlend` for Blend: see-through by alpha, drawn last), `SetTexture(MaterialTexture::BaseColor/Normal/MetallicRoughness/Occlusion/Emissive, handle, SamplerSettings, uvSet)` (keeps `uvSets` in sync, keeps the slot's transform), `SetTextureTransform(slot, TextureTransform{offset, rotation (radians), scale})` (glTF's KHR_texture_transform: scaled, rotated, offset; written into `properties.uvMatrix`/`uvOffset`), `properties.clearcoat`/`clearcoatRoughness` (a varnish layer, 0 = none), `GetTexture(slot)`, `Version()` (bumped by every edit), `IsModified()` (a version other than the one `MarkSaved` noted: the glTF loader and `.material` loading and saving mark it), `Clone()` (same settings and textures, own GPU slot), `CopySettingsFrom(other)` (keeps its GPU slot). The renderer owns the GPU side: `material` (the `Material2` bind group, rebuilt while `BindGroupDirty()`) and a slot in the materials storage buffer, uploaded when dirty via `StandardPBRPipeline::UploadDirtyMaterials`.
- `BuiltinAssets`: white sRGB/linear textures, flat normal, default material (no textures) (persistent), primitive meshes (`builtin://...` keys), `WaterNormalTexture` (256² tiling ripples made from integer-frequency sines, mipmapped, `builtin://texture/water_normal`), `Resolve(assets, key)` (the builtin with that key, made if needed; scene files refer to builtins by key), `InstantiatePrimitive` (an entity drawing one with a material of its own).
- Scene files (`Mariana/Importers/SceneFile.hpp`, `SceneFile.cpp`): `.scene` = JSON with `version`, `dependencies` (every file the scene uses, resource paths: models, `.material` files and their images, an animation graph's clip files, its pipeline), `settings` (`SceneSettings`: `lighting` and `pipeline`; files without it load with `hasLighting` false), `materials` (materials made in memory, e.g. primitives' own and "Make unique" copies, in the `.material` format with textures by `asset` reference; `MaterialJson` (private `Importers/MaterialJson.hpp`) is that format's writer and reader, shared with `MaterialFile`) `materialOverrides` (each a `material` reference into a model, `/Models/X.glb#material/2`, and the material in that format: the model's materials the scene changed since they loaded, `IsModified` and not extracted to a `.material` file (one that was is referred to by that file); loading puts them onto the model's material with `CopySettingsFrom`) and `entities` (parents first: `id`, `name`, `parent`, `components` by ECS name, `tags`). `Save(scene, assets, file, error, settings*)`, `Load(scene, assets, file, error, warnings*, settings*)` (adds to the scene; Clear it first), `Dependencies(file)`. `Signature(scene, assets, settings*)` = an FNV-1a hash of what saving would write (names, hierarchy, each component's fields through a `FieldVisitor` that `SeesFile()`: asset references (with the content of the materials the scene file holds) and lists too, not transient fields; the settings): equal signatures, the same file. `SaveEntity(entity, assets)` / `LoadEntity(entity, assets, state)` = one entity's components (and name) as a file has them, put back onto it (adding, replacing, and removing those it has that weren't saved). A serializer's save visits the component itself (not a copy, which may lose state: an Animator's state machines). Components are described once for both directions by a visitor: `SceneFile::RegisterComponent<T>(name, [](SceneArchive& a, T& c) { a.Field("mass", c.mass); ... })` / `RegisterTag<T>(name)`; `SceneArchive` has `Field` for numbers, bools, strings, vectors, quaternions ([x, y, z, w]), float arrays and lists, enums (as numbers, or by name with a names list), `Asset`/`Assets` (references: `/Models/X.gltf#mesh/3` for what a file holds (loading the file), `/Materials/A.material` for a whole file, `/Textures/x.png#srgb`, `builtin://...`, `#material/N` for the file's own) and `List` of objects; a missing field keeps the component's value; `Transient(name, value)` = a field code reads and writes that files don't keep (a vehicle's driver inputs, a character's walk). The same visit function serves code: `SceneArchive(FieldVisitor&, loading, assets)` sends each field to a `FieldVisitor` (its name, type and where its value is; assets and lists are left out unless it `SeesFile()`: `ForFile()` says which), and `SceneFile::FindComponent(name)` gives a component's serializer (`has`, `save`, `load` (adds it if missing), `remove`, `each`; `ForEachComponent` lists them), which is how scripts reach components by name; an enum field written by name tells a visitor its names. The engine registers LocalTRS, MeshComponent, ShadowCasterTag, CameraComponent, AnimationTargetEntity, SkinComponent and Animator (skeleton, named clips, graph, the graph's `parameters` that differ from its defaults (floats, bools, vectors by name; triggers aren't kept), `states` (each state machine's state away from its entry, `CurrentStates()`, put back with `CrossFadeState`), speed, playing, the clip playing with its loop and time); runtime components (derived transforms, the physics world's) aren't saved, other components are left out with a warning. Asset keys are lower case on Windows, so references take the file's real spelling (`canonical`) and `FileSystem::ToResourcePath`. A save, load and save round trip gives the same file (checked on the 369-entity playground).
- `Submesh::materialIndex` = index into `MeshComponent::materials` (the glTF primitive index; a `MeshSection`'s `materialIndex`).

### Shaders (`engine/resources/Shaders/`)
`test.wgsl` = live PBR shader (forward pass) (GGX, shadow PCF; group 0 = UBO/camera/DrawInfo/ModelData/Material/Bones/shadow maps 0-3 (bindings 6-9) + comparison sampler (10) + sky cubemap (11) + its sampler (12), group 1 = albedo 0, normal 1, metallicRoughness 2, occlusion 3, emissive 4, then one sampler per texture at 5-9 (`albedoSampler` ... `emissiveSampler`), matching the names `SceneRenderer::BuildMaterialBindGroups` binds). Each texture reads `uv` or `uv1` by bit in `MaterialProperties.uvSets`, moved by its texture transform (`textureUV`: `uvMatrix[i]` rows and `uvOffset[i]`; the prepass and shadow alpha tests transform the base color UV the same way); COLOR_0 multiplies base color and alpha; light is gathered as diffuse (sun + sky) and specular (sun + sky reflections + clearcoat), summed for opaque surfaces and, for blended ones (`alphaBlend`), output premultiplied: diffuse times alpha plus specular, alpha = alpha (glass and water keep their highlights), and they skip the screen-space AO; clearcoat (`Material.clearcoat` > 0) adds a GGX lobe and a sky reflection at `clearcoatRoughness` along the geometric normal (normal maps bend only the base), F0 0.04, dimming the layer below by its Fresnel; the vertex shader passes `mirror` (-1 for a negative determinant), which flips the face side and the bitangent; fragments with no normal (points/lines without NORMAL) are drawn unlit. Lighting = sun (`UBO.sunColor`, full-strength shadows) + sky: diffuse from `skyIrradiance(N)` (the SH) and reflections from `skyReflection()` (cubemap mip picked from roughness, fading to the SH when very rough) weighted by `envBRDFApprox` (Karis' analytic split-sum fit), both times AO. Normals: the interpolated tangent frame is re-orthonormalized per pixel and bent by the normal map (xy scaled by `normalMapStrength`); back faces (double-sided only) flip the whole frame via `front_facing`; the shadow lookup offset uses the geometric normal. Both the PBR and shadow shaders read their per-instance data from `DrawInfo[instance_index]` (`transformIndex`, `materialIndex`, `boneOffset`) and skin vertices with `skinMatrix()` (blend of up to 4 `Bones[boneOffset + joint]` matrices, identity when `boneOffset == NO_SKIN`). `skybox.wgsl` live (samples mip 0 only, turned by `skyParams.z`; writes the cubemap pre-inverted through ACES and `camInfo.exposure`, so it reaches the screen as authored, and alpha 0 so it never blooms). `prepass.wgsl` (depth/normals/pick). Effect shaders live in `Shaders/Effects/` (gtao, gtao_blur, bloom_down/up/apply, tonemap, present). In test.wgsl, alpha-tested materials output coverage (alpha sharpened around the cutoff) for alpha to coverage, and the `AmbientOcclusion` graph texture (binding 13, `textureLoad` at the pixel, clamped so the 1x1 fallback works) is combined with the material AO by `min` and applied to sky light only, with `multiBounceAO` and `specularOcclusion`. `outline.wgsl`, `test_old.wgsl` are legacy. WGSL struct layouts must match the C++ structs in `StandardPBR.hpp` / `ICamera.hpp` / `MaterialAsset.hpp`.
- Color: the scene renders linear HDR; only the final effect (tonemap.wgsl, or present.wgsl) tonemaps and encodes with `linearToSrgb`, because the swapchain is deliberately UNORM (`Window::GetSurface`). Color textures are sRGB formats (decoded on sample). `CameraInfo.exposure` is the camera's exposure (`ICamera::SetExposure`; set by the pipeline, 1.5 in Default.pipeline). Emissive can exceed 1 (glTF `KHR_materials_emissive_strength`, or the HDR Emissive control per material in the Mesh inspector). ImGui textures (asset thumbnails) are UNORM.

## Known quirks
- Resting bodies sink up to the penetration slop (5 mm) into what they land on (a dropped 1 m ball rests at y 0.495).
- `FileReader::LoadRawString` logs and throws `std::runtime_error` on a missing file.
- File's Preferences, the Help menu and Edit's Cut/Copy/Paste are TODO placeholders.
- Scene files don't keep the selection (the editor camera is kept per scene in the project's `.mariana`); recent scenes last only for the session. Undoing an edit back to the saved state still marks a `.material` or `.animgraph` file modified (their versions only go up); the scene's own marker compares content.
- `WorldXform.id` slots are never reused, and `Buffer::Write` throws past 131072 transforms.
- `editor/imgui.ini` is tracked in git and changes whenever the layout does. The web build has no ini (it isn't packaged), so its windows start at ImGui's defaults.
- `projects/Sandbox/Models/Sponza/` (Khronos glTF-Sample-Assets Sponza, 51 MB, `.gltf` + external textures) is committed; the editor's web build preloads the whole project, so it makes `index.data` ~110 MB with CarConcept (Khronos glTF-Sample-Assets, glTF-JPG, ~10 MB; the player's ~13 MB). CarConcept's iridescence, material variants and clearcoat textures aren't rendered and its glass blends rather than refracts.
- Blended surfaces aren't in the prepass, so a click on them doesn't pick them (select them in the Hierarchy) and they don't take part in GTAO; they cast no shadow and are sorted per draw (by their bounds' center), not per triangle. It has 3 alpha-masked, double-sided materials (ivy, flowers, chains), handy for testing those paths; the arcades get only sky light, so they stay darker than the courtyard.
