# Mariana Engine (WebGPU)

C++20 game engine + ImGui editor on WebGPU (Google Dawn). One codebase builds native (Windows/MSVC primary) and web (Emscripten → `index.html`, deployed to GitHub Pages from branch `2025`). Author: Noel Pellkvist.

## Build

- Native: `cmake -B build` then `cmake --build build --config Debug --target MarianaEditor -j4` (VS Code task "build Debug"; `--target MarianaPlayer` / "build Player Debug" for the player). Output `build/bin/Debug/MarianaEditor.exe` and `MarianaPlayer.exe`.
- Web: `emcmake cmake -B build-web` then `cmake --build build-web -j4`. Output `build-web/bin/index.html` (+ .js/.wasm/.data) for the editor, `build-web/player/index.html` for the player: a standalone site (index.html/.js/.wasm/.data, nothing else) to upload as is, kept out of `bin/`, which is what Pages publishes. Serve it over http(s); WebGPU needs a secure context (https, or localhost). `mariana_web_app()` (`cmake/MarianaWeb.cmake`) sets the shell (`editor/shell.html`, `runtime/shell.html`), ASYNCIFY, GLFW3, a 1 MB stack (Jolt asks for it) and preloads the engine's resources plus the app's folders or single files (at their absolute paths; files as `path@path`; `.mariana` cache folders are excluded); the engine adds `-fexceptions` (public) and `FLECS_NO_THREADS`.
- CI: `.github/workflows/pages.yml` (emsdk 4.0.16) builds web and deploys `build-web/bin` to Pages. The only test is `MarianaPhysicsTest` (native, console, no window or GPU; `physics/tests/SmokeTest.cpp`): it runs `physics/tests/Scenarios.hpp` (scenarios with known answers, no window or GPU: box stack, resting ball, pendulum period, the primitive car's acceleration, stairs, a float and a sinker in water, a limp ragdoll of a skeleton built in code falling to the ground, a cloth hanging from two corners, a pumped-up ball, the jelly and balloon presets, the primitive car and a character driven into jellies; soft bodies' meshes exist only on the CPU there) on Jolt's thread pool and exits 1 when one fails; the web build gives the same numbers single-threaded.
- Each target globs its own `source/**/*.cpp` — new .cpp files need a CMake re-configure (CONFIGURE_DEPENDS handles it on build).
- Resource paths are given as `"/Shaders/x.wgsl"` and resolved by `FileSystem` (`Mariana/Foundation/FileSystem.hpp`): a list of root folders searched in order, the app's (`AddRoot`, the latest first) before the engine's (`MARIANA_ENGINE_RESOURCES`, a compile definition of the engine; `SetEngineRoot`). `FileReader`, `Texture::LoadTexture`, the window icon and effect/pipeline files go through `Resolve`; `RenderPipelineDesc::Save` through `ResolveForWrite` (the existing file, or new under the first root). A project can override an engine file by putting one at the same path. OS paths (e.g. what the Assets browser drags) are not resource paths; `ToResourcePath(file)` turns one under a root back into one (matching without case on Windows, keeping the file's spelling).

## Layout

- `engine/` → static library **MarianaEngine**: everything a game needs at runtime. Public headers in `engine/include/Mariana/<Module>/`, included as `<Mariana/Module/X.hpp>`; sources in `engine/source/<Module>/` (private headers too, e.g. `Graphics/Init.hpp`, included as `"Graphics/Init.hpp"`). Modules, each using only the ones before it: `Foundation` (Logger, FileReader, FileSystem, `Image` (CPU RGBA8: Load, SavePNG, Downscale by halving with alpha-weighted colors), `FileWatcher`, `TaskQueue`, `GameClock`), `Graphics` (GPU context, Buffer + layouts, Texture, Shader2, Material2, Mesh, Renderpass, NativeGPU), `Platform` (Window, IInput), `Scene` (ECS, Prefab), `Assets`, `Geometry` (StandardVertex, MeshBuilder, Primitives), `Animation` (Skeleton, AnimationClip, Pose, AnimationGraph, Animator, Skin), `Rendering` (Renderer, RenderGraph, SceneRenderer, SceneView, SceneCamera, Effect, RenderPipeline, StandardPBR, SkyLight, ICamera, MaterialAsset, BuiltinAssets, Components), `Importers` (GLTFLoader, ImageImporter, MaterialFile, AnimationGraphFile); `Mariana/Application.hpp` sits on top. glm, Dawn and GLFW are public dependencies, flecs/json/stb/tinygltf private.
- `physics/` → static library **MarianaPhysics** (see Physics below): rigid bodies and colliders on Jolt, for apps that want them. Public headers in `physics/include/Mariana/Physics/`, sources (and the private `JoltCommon.hpp`) in `physics/source/`. Links MarianaEngine publicly and Jolt privately; no UI.
- `editor/` → executable **MarianaEditor**: `EditorApp`, the ImGui layer (`Editor/GUI.hpp`), windows, inspector drawers, editor camera, ImGuizmo, the physics UI (`Editor/Physics/`). Headers in `editor/include/Editor/`, sources in `editor/source/`. Links MarianaEngine + MarianaPhysics + imgui.
- `runtime/` → executable **MarianaPlayer**: runs a project without the editor or any UI. `PlayerApp` (an `Application`) reads the project's `/Player.json` (`PlayerConfig`: window, pipeline, camera position/target/orbit speed, prefabs or primitives (cube/sphere/plane/cylinder/capsule with a `color`) to spawn with position, Euler `rotation`, scale (a number or per axis), `faceCamera` to turn a prefab's +Z front toward the camera, presets (car/motorcycle/tank/playground/character/course/chain/door/spinner/wrecking ball/pool/ragdoll/flag/drape/jelly/balloon), and a `physics` block (`body` static/kinematic/dynamic, `collider` box/sphere/capsule/cylinder fitted on the root, mesh/convex on every mesh, or none; `mass`, `friction`, `bounciness`, `velocity`; format in `PlayerApp.hpp`), and `"vehicle": "car"` to rig a prefab as a drivable car (`VehiclePresets::RigCar`), `"ragdoll"` to give an animated prefab a `Ragdoll` (a mode, or an object with `mode`, `mass`, `limpOnImpact`, `knockback`, `knockbackLift`), and `scene`, a scene file loaded first (the spawns go on top); `camera.follow` chases the driven vehicle), sets up the renderer, scene renderer, one scene view, effects, animation and physics (always running, with the project's `/Physics.json` if it has one) like the editor, and draws with a `PlayerCamera` (look-at, optional orbit). Headers in `runtime/include/Player/`. Its web build packages only what `Player.json` uses (CMake reads it with `string(JSON)`: Player.json, the project's Physics.json if any, a project-local pipeline, the scene and every file its `dependencies` list, each prefab; a `.gltf` with its whole folder, a `.glb` with its `.materials` folder (`mariana_player_add_file`); editing Player.json or the scene re-configures) and uses the minimal `runtime/shell.html` (black page, canvas scaled to fit with CSS only, loading percentage).
- The engine never includes editor code or ImGui; keep it that way (its include path has no editor folder, so a stray include fails to build). Neither does MarianaPhysics, and the engine knows nothing of physics.
- Resources: `engine/resources/` (Shaders, Effects, Pipelines, the default sky in Textures/skybox), `editor/resources/` (font, window icon, `Thumbnails/`: the thumbnail pipeline, its tonemap effect and shader), `projects/Sandbox/` (sample content: Models incl. Sponza and CarConcept (CC BY 4.0, credited in its `README.md` and the repo README), Textures). The editor's `main.cpp` adds the editor and project roots; `MARIANA_PROJECT_DIR` (editor compile definition) is the project it opens. `editor/imgui.ini` is the editor layout (`io.IniFilename`, `MARIANA_EDITOR_DIR`).

## Architecture

Entry: `editor/source/main.cpp` → `EditorApp().Start()`.

- **Globals** (`engine/source/Graphics/Init.{hpp,cpp}`, private to the engine): `instance`, `adapter`, `device`, `surface`, `windowFormat`, `deviceLimits`. `Init()` creates them synchronously via `WaitAny`. Include `"Init.hpp"` from .cpp files only.
- **Pimpl everywhere**: public headers avoid `webgpu_cpp.h`; GPU handles live in `struct Impl` and are returned as `void*` (`GetTextureView()`, `GetBuffer()`, `GetPipeline()`), cast back to `wgpu::*` in .cpp. The exception is `NativeGPU.hpp` (`NativeGPU::Device()`, `SurfaceFormat()`), for code outside the engine that talks to WebGPU itself (the ImGui backend).
- **Application** (`Mariana/Application.hpp`, in the engine): the app base class. Its constructor takes the app's `WindowSettings` (title, size, icon; the engine has no defaults). Owns `Window`, `IInput`, `std::unique_ptr<ICamera> cam` (set by the app), `assets` and `gameClock`. Loop: `Window::FollowCanvas` (web: the window follows a canvas the page resized) → `gameClock.Tick(dt)` → `OnUpdate(dt)` (real time) → cam update → `OnGUI` → `OnRender` → `input.Update`. Native loop presents + `ProcessEvents`; web uses `emscripten_set_main_loop_arg`.
- **Game time** (`Mariana/Foundation/GameClock.hpp`): `GameClock` runs only in play mode (`Play`, `Pause`, `Stop`, `Step` = one 1/60 s frame while paused, `timeScale`, frames longer than 0.25 s count as 0.25 s); `DeltaTime()` is 0 unless the game runs, `Time()`/`Frame()` count from Play. Game systems step with `gameClock.DeltaTime()` (the animation system in both apps); the app's own things (editor camera, UI) use the real `OnUpdate` delta. The player calls `Play()` at the end of `OnStart`; the editor starts stopped.
- **Window**: GLFW, sRGB surface format preferred, Fifo present, resize callback, F11 fullscreen.
- **GUI** (editor only, owned by `EditorApp`): ImGui GLFW + WGPU backends, docking over viewport (`DockSpaceId()`, `CentralNodeId()`), windows move by their title bar only, custom "Mariana" style, JetBrainsMono Nerd Font. `EditorApp` inits it in `OnStart`, starts the frame in `OnGUI` and draws it with `Renderer::RenderOverlay` (the only thing on the screen).

### ECS (`Mariana/Scene/ECS.hpp`, `Prefab.hpp`)
Opaque wrapper over flecs; headers never include flecs.
- `Scene` (owns `flecs::world`), `Entity` (Scene* + uint64 id), `System` (flecs query + type-erased callback via `CreateSystem<Comps...>(fn(Entity, Comps&..., float dt))`; run manually with `.Run()`).
- Components must be registered by name: `ECS::RegisterComponent<T>("Name")` / `ECS::RegisterTag<T>("Name")` then `scene.UpdateComponentRegistry()`. Names matter — prefab cloning and the inspector look components up by name. The ECS's own components register themselves when a `Scene` is constructed (`ECS::RegisterBuiltinComponents`); modules provide `RegisterComponents()` for theirs (`Animator::`, `SceneRenderer::`), which the app calls.
- Built-ins: `NameComponent`, `LocalTRS` (pos, quat xyzw, scale, `version`), `WorldXform` (model[16], normal[9], `id`, `version`), `XformCache`, `TransformClock`. A flecs system (`cascade` on the parent term, so parents always update before children; the parent's WorldXform/XformCache arrive as query terms) recomputes `WorldXform` and bumps `WorldXform.version` when `LocalTRS.version` or the parent changes. Mutate via `SetPosition/SetRotationQuat/SetScale` (they bump the version only if the value changed), or write `LocalTRS` and `++version` yourself.
- Typed access (`Has/Get/TryGet/Add`) goes through `ECS::detail::TypeSlot<T>()`, a per-type index into `Scene::Impl::slot_ids`, so it never hashes `type_info`. System queries are cached (`EcsQueryCacheAuto`) and walk field arrays per table. `ForEachRoot` uses a cached `!ChildOf` query.
- `WorldXform.id` is a per-scene monotonically increasing slot index into the GPU transform storage array.
- Hierarchy = flecs `ChildOf`. `Prefab` owns its own `Scene`; `Scene::Instantiate(prefab)` deep-clones by component name (skips WorldXform/cache/clock). `Scene::Clear()` destroys every entity and restarts the transform slots at 0 (pair it with `SceneRenderer::InvalidateTransforms()`). `Scene::Snapshot()` copies every entity into a `SceneSnapshot` (its own Scene: components by name, no derived ones, plus each entity's id, parent and transform slot, parents first); `Scene::Restore(snapshot)` detaches the snapshot's entities, destroys everything made since, brings destroyed ones back under their old ids (`ecs_make_alive`; a fresh id only if the index was taken), and resets each one's components, parent and transform slot (and the slot counter), so ids held elsewhere (selection, skin joints) stay valid. Pair it with `InvalidateTransforms` too.

### Rendering (`Mariana/Rendering/`, on top of the GPU wrappers in `Mariana/Graphics/`)
- `Renderer` owns `RenderGraph graph`; `Render(overlay)` executes the graph (whatever writes "Backbuffer" ends up on screen), then calls the optional `Renderer::Overlay` with a pass that loads the backbuffer and has no depth (the editor draws ImGui there). `RenderToTexture(target)` executes it into a render texture instead (offscreen: the editor's views, thumbnails); the static `RenderOverlay(overlay)` puts only the overlay on a cleared screen. Set the graph's backbuffer format and output size before adding passes that render to the screen.
- `RenderGraph` (`Rendering/RenderGraph.hpp`): named textures (`GraphTextureDesc`: format, `scale` of the output size or fixed `width`/`height`, `msaa`) and passes (`GraphPassDesc`: `colorTargets`, `resolveTargets`, `depthTarget`, `reads`, `keep`, `record(Renderpass&)`). `Compile()` orders passes topologically by what they read and write (insertion order otherwise; a later writer of a texture depends on earlier ones and loads instead of clearing), culls passes not needed for the backbuffer or a `keep` pass, creates every declared texture at its size (recreated on `SetOutputSize`), and calls the `OnTexturesChanged` callbacks after every compile so owners rebind. `SetFallback(name, tex)` = what readers get when nothing writes a name. Passes, textures and callbacks carry an owner; `RemoveOwner` removes a feature or effect. `AddPass` returns the pass's `Renderpass` immediately so shaders can be built against it; `Execute` recompiles when anything changed. Disabled passes (`Renderpass::SetEnabled(false)`) keep their previous contents.
- `Renderpass(msaa, depth, outputFormats, w, h)`: render graph passes get their textures through `SetTargets` (nullptr color = backbuffer) and `SetLoadOps`; standalone passes can still own targets (`Init`/`Recreate`). With `msaa` (`IsMSAA()`) the targets have 4 samples and resolve at the end of the pass into `GetRenderResloveTarget(i)` (the samples are discarded). Draws come from its `renderSystem` (an ECS System) and/or `recordCallback`, via `SetShader2(shader, variant = ShaderVariant::Default) / SetMesh / SetMaterial2 / Draw(indexCount, startIndex, firstInstance, instanceCount = 1)`. Redundant pipeline/mesh/material binds are skipped (switching only the variant keeps the bound groups); the shader's non-material groups are bound once per shader switch.
- `Shader2` builder: `.Group(i).AddBuffer/AddTexture/AddSampler(name, binding, ...)`, `.SetMaterialGroup(i)`, `.SetVertexStructLayout`, `.SetWGSL`, `.SetRenderpass`, `.Build(shadow)`. Pipeline hardcodes: entry points `vertexMain`/`fragmentMain`, front face CW, back-cull (none for shadow), depth LessEqual Depth24Plus, sample count from the renderpass (4 for MSAA passes, which also get the `AlphaToCoverage*` variants). `RebuildBindGroups()` recreates the shader's own groups after textures it reads were resized. Without `SetVertexStructLayout` the pipeline takes no vertex buffers and no culling (fullscreen passes; draw with `Renderpass::DrawFullscreen()`), and a renderpass without depth gets no depth state. `.SetDrawVariants(true)` also builds the other `ShaderVariant` pipelines on the same layout (`Renderpass.hpp`: `DoubleSided` = no culling, `Mirrored` = front-face culling for negative-determinant transforms, `Lines`, `Points`); `.SetDepthOnlyFragment(true)` keeps the fragment stage in a pass without color outputs (alpha-tested shadows). Samplers: `SamplerType_Repeat` (default; linear mag, nearest min, linear mips), `SamplerType_Comparison`, `SamplerType_LinearClamp` (linear everything, clamped). `BindTexture(name, tex)` re-points one of the shader's own texture bindings after Build (then `RebuildBindGroups()`).
- `Material2`: copies the shader's material bind group layout, `.SetTexture(name, tex)`, optional `.SetSampler(name, SamplerSettings)` (per-material address/filter/mip settings overriding the sampler's type), `.Build()`.
- `Buffer` + layouts (`UniformLayout.hpp`, `StorageBufferLayout.hpp`): layouts are built reflectively from a sample object + member refs and pack to WGSL alignment (vec3→16, mat columns stride 16). `StorageArrayLayout(count, obj, fields...)` for `array<T>`; `Buffer::Write(obj, index)`. Dynamic uniform buffers allocate stride*1024. `RawBufferLayout{size, type}` = a buffer packed by its user (written with `WriteRawBytes`), e.g. effect parameters.
- `VertexBufferLayout{v, v.field...}` builds the vertex layout from a struct. The standard renderer's vertex is `StandardVertex` (`Mariana/Geometry/Vertex.hpp`: position, normal, tangent, texcoord0/1, color0, boneIndices(uvec4), boneWeights).
- `StandardPBR.*`: `StandardPBRPipeline` = the scene's shared storage arrays (131072 elems) for transforms, materials and bones (transforms are staged with `QueueTransform` and sent by `FlushTransforms` in a few writes, runs of nearby slots); `StandardPBRView` = what each view has of its own: the UBO (lightDir, cascades, `sunColor`, `skySH[9]`, `skyParams`), camera UBO, draw data array and the shadow cascades' dynamic uniform.
- `Texture`: `TextureFormat` enum mirrors `wgpu::TextureFormat` values (cast directly). Load/Upload/Rescale (bilinear, CPU)/Cube/RenderTexture/Depth; `CreateTexture(..., mipLevels)` + `UploadTextureWithMips` (CPU box-filtered chain, any array layer); `CreateCubeTexture(faces, size, format)` uploads 6 faces with full mip chains (`LoadCubeTexture` loads files then calls it). `RequestPixelReadback(x,y)` / `TryGetPixelReadback(value)` = one async 1x1 readback in flight; `RequestImageReadback()` / `TryGetImageReadback(rgba)` = the same for all of mip 0 of an RGBA8 texture (rows padded to 256 bytes in the buffer, returned packed). `GetDisplayView(mip = -1)` = a view for showing the texture in a UI: sRGB textures are created with their UNORM sibling as a view format, so previews show the stored colors (cached per mip); `GetMipLevelCount()`.
- `IMesh`: `VertexCount()/IndexCount()` are what was uploaded; object-space `boundsMin/boundsMax` are computed by `BuildMesh` when the vertex has `.position`, plus `jointBounds` (bind-pose `Bounds` of the vertices each joint influences, indexed like `boneIndices`) when it also has bone indices/weights. `Submesh::topology` is `Triangles`, `Lines` or `Points`.
- Geometry (`Mariana/Geometry/`): meshes are built from `MeshSection`s (vertices, indices (empty = in order), `SourceTopology` incl. strips/fans/loops, `materialIndex`, `hasNormals`, `hasTangents`). `BuildMesh(sections)` converts each section to a list topology (`Geometry::ToListTopology`), gives triangle sections without normals flat normals (`GenerateFlatNormals`, de-indexed) and tangents where missing (`GenerateTangents`, Lengyel's method, w so the bitangent points up the texture as glTF expects), makes one submesh per section, uses 16-bit indices when <= 65536 vertices, uploads and frees the CPU arrays, keeping only the positions and the triangle submeshes' indices for physics (`IMesh::collision`, a shared `MeshCollisionData`; nullptr without triangles). It is `UploadMesh(PrepareMesh(sections))`: `PrepareMesh` is the CPU part (a `MeshData`: vertices, indices, submeshes; any thread), `UploadMesh` the GPU part. Both take a `MeshUsage` (`Mesh.hpp`): Static (default) frees the CPU data; KeepData keeps a copy as `IMesh::source` (the builtin primitives do, so a soft body can copy one); Dynamic keeps it too and makes the vertex buffer writable: `IMesh::WriteVertices(vertices, count, size, bounds)` replaces every vertex and the bounds and bumps `deformVersion` (part of a shadow caster's version, so its shadow is redrawn). Without a GPU device (the console test) a mesh gets no buffers, only its CPU side. `Primitives::Cube(size, subdivisions)/Plane/Sphere/Cylinder/Capsule` return sections (front faces outward, wound like glTF: the front is where cross(p1 - p0, p2 - p0) points); `BuiltinAssets::PrimitiveMesh(assets, BuiltinMesh::...)` shares built ones (`builtin://mesh/...`, kept on the CPU; `Grid` (a 1 m square in XZ, 24 x 24 cells) and `SubdividedCube` (8 x 8 cells a face) are for soft bodies). Importers and procedural code both go through this.
- The scene renderer is split in two. `SceneRenderer` (`Rendering/SceneRenderer.hpp`) = the scene's GPU data, shared by every view of it: transforms, material constants and bind groups, the skins' bones, the sky (cubemap, SH, mesh), `lighting` and settings. `RegisterComponents()` (MeshComponent, SkinComponent, ShadowCasterTag, CameraComponent; all but SkinComponent are in `Rendering/Components.hpp`) before `UpdateComponentRegistry`; `Init()` loads the sky and makes its systems; `Update()` once per frame (only when some view draws) uploads changed transforms and dirty material constants and poses the skins. `SetSettings(SceneRendererSettings)` changes `shadows`, `shadowDistance`, `shadowMapSize` and `sky` (the sky as background; off leaves SceneColor clear, alpha 0); the views apply it when they next prepare (a new size re-adds their maps; the graph recreates them and `BindGraphTextures` rebinds). `InvalidateShadows()` bumps an epoch every view compares. `SceneView` (`Rendering/SceneView.hpp`) = one camera's view of it in a render graph: `Init(graph)` adds its textures and passes, compiles and builds its shaders (`pbrShader` = test.wgsl, `skyboxShader`, `shadowShader`/`shadowMaskedShader` = shadow.wgsl, `prepassShader`; their group 0 binds the shared arrays and the view's own buffers); `Prepare(camera)` once per frame per view uploads its camera, lighting and cascades, builds material bind groups (`SceneRenderer::BuildMaterialBindGroups`: every material whose textures changed, against the view's `pbrShader` material group, which every view declares the same, so the first view to see a material builds it for all; empty slots get white sRGB / flat normal / white linear) and builds its draw lists. `CameraBuffer()` is what its effects read. Another view adds only its own camera, draws, shadow maps and graph textures. Graph textures: `ShadowMap0..3` (fixed `shadowMapSize`², Depth24Plus), `SceneDepth` + `SceneNormals` (RGB10A2, view space) + `EntityIds` (RGBA16Uint) from the "Prepass", `SceneColorMS`/`SceneDepthMS` (4x MSAA) resolved into `SceneColor` (RGBA16Float) by the "Forward" pass, which reads the shadow maps and `AmbientOcclusion` (R8, white 1x1 fallback when no effect writes it; test.wgsl clamps its `textureLoad`). The prepass is `keep` while the view's `writeEntityIds` (editor picking). The sky is an inward-facing `Primitives::Cube` drawn last with skybox.wgsl.
- Frame (inside `SceneView::Prepare`/`BuildDrawLists`): frustum-cull (mesh bounds vs camera/light frustum), sort by (variant, material, mesh, submesh), and turn each run into one instanced draw whose instances read consecutive `DrawData` entries (`frameDraws`, one write). Submeshes with a Blend material go to `blendedItems` instead: drawn one by one after the sky in the Forward pass, farthest first (by the distance of their bounds' center), with the `Blended`/`BlendedDoubleSided` pipelines (premultiplied alpha over what is there: src One, dst OneMinusSrcAlpha; depth tested, not written). Each draw picks a `ShaderVariant` (`DrawVariant()`: lines/points by topology, else `DoubleSided` for `MaterialAsset::doubleSided`, else `Mirrored` for a negative-determinant transform; alpha-tested materials use the `AlphaToCoverage*` variants). The prepass draws the same batches (not the blended ones).
- Shadows (per view): cascaded shadow maps (`kShadowCascades` = 4 maps, a constant in `StandardPBR.hpp`; size and distance from `SceneRendererSettings`, default 2048² out to 80 m). `UpdateShadowCascades()` splits the view (75% log / 25% uniform), fits each slice with a rotation-invariant sphere, snaps it to whole texels (no shimmering), and writes `UBO.cascadeVP/cascadeSplits/cascadeTexel` plus each cascade's matrix into the dynamic uniform `shadowCascadeBuffer` (`SetBufferIndex("ShadowCascade", c)` in the cascade's pass). Each cascade (graph pass "Shadow cascade c") culls casters against its own light volume and is skipped while its matrix and casters are unchanged (the light direction and alpha-tested materials' `Version()` are tracked, a cascade without casters ignores its matrix; `InvalidateShadows()` forces a redraw). With `shadows` off no casters are gathered, so the maps are cleared once and then skipped. Points, lines and blended surfaces cast no shadows. Casters are drawn whole (one index range, no fragment stage) except alpha-tested submeshes (material `alphaCutoff > 0`): those are drawn separately with `ShadowMapMaskedShader` (same `shadow.wgsl` plus a discarding fragment stage; its group 1 matches the PBR material group, so material bind groups are reused), and the opaque remainder of such a mesh is merged into contiguous index ranges. The shadow pipelines use slope-scaled depth bias (`Shader2::Build(true)`); receivers use a normal offset, 16-tap filtered PCF, blending between cascades, and a fade at the shadow distance.
- Skinning (GPU): glTF skins load as `Skin` assets (joint node indices + inverse bind matrices, `Mariana/Animation/Skin.hpp`); skinned nodes get `SkinComponent`, whose joints are resolved by node index from the model's wrapper root (`ResolveJoints` in `SceneRenderer.cpp`). Each frame `SceneRenderer::Update`'s `skinningSystem` writes `inverse(meshWorld) * jointWorld * inverseBind` per joint into `frameBones` (one `boneBuffer` write; `BoneData` is just the matrix, normals use its 3x3) and sets `SkinComponent::boneOffset`; draws carry it in `DrawData::boneOffset` (`~0u` = not skinned). It also moves each of the mesh's `jointBounds` by `jointWorld * inverseBind` into `SkinComponent::bounds` (world space, exact for linear blend skinning), which the camera and every shadow cascade cull against (empty bounds = never culled). The pose version feeds the shadow cache. The skinned mesh node's own transform is effectively ignored, per the glTF spec.
- Cameras in the scene: `CameraComponent` (fov, near, far; `Rendering/Components.hpp`) on an entity that looks along its +z with +y up; `SceneCamera` (`Rendering/SceneCamera.hpp`, an `ICamera`) follows one (`Follow(world, camera)`, then `SetViewportSize` and `UpdateBuffer`).
- Lighting: `SceneRenderer::lighting` (`LightingSettings` in `StandardPBR.hpp`: sun azimuth/elevation/color/intensity, sky diffuse and reflection intensity, `skyRotation` = degrees the sky is turned around +y) is turned into the UBO each frame (a sun direction change redraws the shadows). The rotation (`UBO.skyParams.z`, radians) turns the sky's light, its reflections (`toSky()` in test.wgsl) and the drawn sky (skybox.wgsl reads the UBO at binding 3) together. `SceneRenderer::SkyDirection()` (`SkyBrightestDirection(sh)`) = where the sky's light comes from most, before the rotation; the default sky is brightest toward -z. The skybox cubemap is loaded in `Init` via `CreateCubeTexture` (mips for blurry reflections) and `ComputeSkyIrradianceSH` (`SkyLight.hpp`: L2 spherical harmonics of the sky, cosine-convolved and divided by pi) fills `ubo.skySH`. Each draw picks a `ShaderVariant` (`DrawVariant()`: lines/points by submesh topology, else `DoubleSided` for `MaterialAsset::doubleSided`, else `Mirrored` when the world transform's determinant is negative); draws sort by variant first.
- Effects (`Rendering/Effect.hpp`, files in `engine/resources/Effects/*.effect`, shaders in `engine/resources/Shaders/Effects/`): an effect file (JSON) declares `stage` ("BeforeLighting" writes scene textures the forward pass reads, e.g. GTAO writes `AmbientOcclusion`; "PostProcess" runs on the HDR image), `final` (writes the screen, always last: Tonemap), `parameters` (float/int/bool/vec2-4/color3-4 with default/min/max, packed in file order with WGSL layout into a uniform `params`), private `textures` (format, scale or size) and `passes` (shader, `inputs` binding name -> texture, `output`, per-pass `constants`). Names are private textures, `Input`/`Output` (the post chain) or any graph texture. Each pass shader only defines `fragmentMain(input: FullscreenInput)`; the effect system prepends `params`, `passInfo` (outputSize xy/zw, constants), `camera` (CameraInfo), `linearClamp`, the inputs (depth formats as `texture_depth_2d`) and the fullscreen vertex shader. `EffectStack` (one per view, owned by the app) loads effects (`Add(path)`, or `Add(definition)` to reuse a loaded one), removes, moves within a stage, and rebuilds its part of the graph when effects are added, removed, moved or toggled (pipelines are kept when formats don't change); post effects chain through `PostColor<i>` textures from `SceneColor` to the backbuffer, and `Present.effect` is used when no final effect is enabled. Exposure is the camera's (`ICamera::SetExposure`), read by tonemap.wgsl and skybox.wgsl.
- Render pipelines as data (`Rendering/RenderPipeline.hpp`, files in `Pipelines/*.pipeline` under any root, the default in `engine/resources/Pipelines/`): `RenderPipelineDesc` = name, `exposure`, `scene` (`SceneRendererSettings`) and `effects` (effect file path, `enabled`, parameter values by name). `Load(path, desc, error)` / `Save(path, error)` (JSON, see the header; missing values keep defaults, unknown parameters warn on Apply), `Apply(effects, sceneRenderer, camera*)` (clears the stack and loads every effect file anew), `Capture(effects, sceneRenderer, camera*)` = what runs now. It is plain data, so code (and later scripts) can build, edit and apply one; custom shaders and bindings come in through effect files.

### Physics (`physics/` → MarianaPhysics, on Jolt Physics)
- Jolt stays private: public headers use glm and engine types only. `JoltCommon.hpp`: glm/Jolt conversions; layers (object layer = `(user layer << 1) | moving`, broad phase Static/Moving, a pair filter from the settings' matrix; two static bodies never collide); `ColliderMaterial` (a `PhysicsMaterial` carrying each collider's friction and restitution on its sub-shape; contacts combine friction by the geometric mean and restitution by the max; a soft body has no sub-shapes, so its own are used, and Jolt asks for what is near a soft body with an empty sub-shape id, which a body of several colliders can't look up (the index would be past the end: a crash on the web), so that gets the body's own, its first collider's: `ContactMaterial`). Jolt's trace and asserts go to the Logger.
- Components (`Mariana/Physics/Components.hpp`; `PhysicsWorld::RegisterComponents()`: "RigidBody", "BoxCollider", "SphereCollider", "CapsuleCollider", "CylinderCollider", "MeshCollider", and "Joint", "Vehicle", "VehicleWheel", "CharacterController", "PlayerControl", "FollowCamera"): `RigidBody` (`motion` Static/Kinematic/Dynamic, `mass` (0 = the colliders' volume times density), damping, `gravityFactor`, `continuous` (Jolt LinearCast), `allowSleeping`, `lockedAxes` (`LockedAxis` bits, world space; all six make it kinematic), `layer`, start velocities). Colliders derive from `Collider` (center, rotation, friction, restitution, density, `isTrigger`): box `size`, sphere `radius`, capsule and cylinder `radius` + `height` along local Y (the capsule's tip to tip), `MeshCollider` (`mesh`, empty = the entity's MeshComponent mesh; `convex` = its convex hull; a triangle mesh on a dynamic body is used as its hull, with a warning; scaled in the mesh's own axes, then turned by the collider's rotation). Unity's rules: a RigidBody's body is its colliders plus its descendants' down to the next RigidBody (a StaticCompound; a single offset collider is a RotatedTranslated shape); colliders with no RigidBody on or above them are a static body of their own; scale scales the shapes (boxes per axis, round shapes by the larger radial scale). Triggers are sensors that also notice static and kinematic bodies; a body with solid colliders and triggers gets a second, kinematic sensor body that follows it. `ColliderGeometry.hpp`: `ForEachCollider(entity, transform, fn)` = the shapes as placed (also what the editor draws; meshes carry their `MeshCollisionData`, bounds and scale), `HasCollider`, `ColliderMesh`, `MeshBounds(entity)` (its mesh's bounds, or for a model's root those of the meshes below it) and `FitColliders(entity)` (box/sphere/capsule/cylinder to those bounds; a flat mesh gets a 0.1 thick slab under its surface). `Shapes.cpp` (private) makes the Jolt shapes; `ShapeCache` keeps triangle meshes (`MeshShape`, vertices welded by position so seams aren't open edges) and convex hulls per mesh and surface, unscaled (a `ScaledShape` scales them), for as long as the mesh lives, so Play after Play reuses them (Sponza's takes ~0.35 s on the web the first time). The world's code is split over `WorldImpl.hpp` (the `Impl`), `PhysicsWorld.cpp` (sync, steps, contacts), `Queries.cpp` and `DebugDraw.cpp`.
- `PhysicsWorld` (`Mariana/Physics/PhysicsWorld.hpp`, one per scene, owned by the app): a Jolt `PhysicsSystem` (65536 bodies), 16 MB temp allocator, `JobSystemThreadPool` natively / `JobSystemSingleThreaded` on the web. `Step(dt)` with game time: first `Sync` (walks the hierarchy, bodies made in entity id order; a body is made again when its signature changes, an FNV hash of its RigidBody and collider geometry, keeping a dynamic body's velocity; bodies whose entity or components went are removed; a static body moved by the editor or code is moved, a dynamic one whose `LocalTRS.version` isn't the one it wrote is teleported), then fixed steps (`fixedTimestep`; an accumulator with a 1e-6 tolerance so a Step button frame is exactly one step; at most `maxStepsPerFrame`, then time is dropped): kinematic bodies `MoveKinematic` to their entity, Jolt `Update`, and `TrackPoses` keeps where each dynamic body (and character) was after the last two steps. Then every Step call (also one that ran no step) shows them: dynamic bodies write their entity's `LocalTRS` (in the parent's space, parents first; `++version` only when it changed), so rendering and children follow as with animation, with `PhysicsSettings::interpolation` (and `RigidBody::interpolate`) between the last two steps by `accumulator / fixedTimestep` (smooth on any frame rate, one step behind), else where the last step left them; wheels are placed on the chassis as shown. `ShowLatest()` writes the latest poses (the editor calls it while paused, so Step shows its step). Bodies belong to the world (entity id -> record), not to components, so copies (prefab instances, snapshots) get their own. `Reset()` drops every body and makes a new `PhysicsSystem`: the same scene then simulates exactly the same way each time (two Play runs match pixel for pixel). `GetBodyInfo(entity, info)` (motion, sleeping, sensor, mass, velocities), `BodyCount()`, `ActiveBodyCount()`.
- Queries (`Queries.hpp` types; against the bodies as the last Step left them): `Raycast` / `RaycastAll` (nearest first, once per body) / `ShapeCast` (`QueryShape::Sphere/Box/Capsule`, turned; a shape already touching something hits it at 0) give `RaycastHit` (entity, point, normal, distance); `Overlap` the entities a shape touches (sorted by id). `QueryFilter`: a layer bit mask, `triggers` (off by default), one entity to `ignore`. Forces on dynamic bodies (false without a dynamic RigidBody): `AddForce`/`AddForceAtPoint`/`AddTorque` act through every fixed step of the next Step call (call them each frame for a steady push; queued even before the body exists), `AddImpulse`/`AddImpulseAtPoint`/`AddAngularImpulse` once; `SetVelocity`/`GetVelocity`, `Teleport` (entity and body at once, so queries see it), `WakeUp`. Checked: an impulse of 10 N s on 2 kg gives exactly 5 m/s, 1 s of 20 N exactly 10 m/s.
- Contact events: `Events()` = the `ContactEvent`s (Begin/End, entities `a` and `b` with the trigger as `a`, `trigger`; on Begin the point, normal from a to b and approach `speed`) of the last Step call, once per pair of bodies however many sub-shapes touch, sorted so threads don't change their order; `IsTouching(a, b)`. Jolt reports per sub-shape pair from its worker threads (`ContactCollector`, locked) and also drops a body's contacts when it falls asleep; those are kept as asleep and only end if the bodies have been awake two steps without the contact coming back, so a body resting in a trigger never "leaves" it by sleeping. Contacts of removed bodies end in the next step.
- Debug view: `DebugDraw(PhysicsDebugDraw, lines)` appends `DebugLine`s (RGBA8, red low byte, as ImGui's) from Jolt's `DrawBodies` through one process-wide `DebugRendererSimple` (shapes in wireframe coloured by motion type or awake/asleep, bounding boxes, centers of mass, velocities; round shapes' detail from `cameraPosition`; at most `maxLines`), plus the contact manifolds Jolt drew during the steps since `contacts` was asked for (`ContactConstraintManager::sDrawContactManifolds` only while stepping). Needs `JPH_DEBUG_RENDERER` (Jolt defines it publicly in Debug and Release).

- Vehicles (`Mariana/Physics/Vehicle.hpp`, `Vehicles.cpp`; Jolt's `VehicleConstraint`): a `Vehicle` on an entity with a dynamic RigidBody (the chassis; its colliders are the body; `RigidBody::centerOfMass` lowers it) and a `VehicleWheel` on each wheel entity below it (not below another body). The chassis drives along +Z, +Y up, +X right; Jolt's right is -X, so steering is passed negated and Jolt's left track/differential side is +X. A wheel entity sits where its wheel hangs with the suspension fully out (the attachment is `suspensionMax` above it, along the suspension tilted forward by `casterAngle`); colliders on or below wheels are left out of the chassis (`Collect` stops at them). `SyncVehicles` (end of `Sync`) makes a constraint per chassis (wheels in entity id order) and makes it again when the Vehicle's settings (not its driver inputs), the wheels or the chassis body change; wheel placements come from LocalTRS values and the chassis's scale chain, never world matrices (their rounding changes as it moves and would rebuild it every step). Types: `Wheeled` (`WheeledVehicleController`: engine torque/RPM range, automatic or manual (`gear`) gearbox with shift RPMs, clutch, gear ratios, reverse; axles = wheels within 0.2 m in z, frontmost first; `drive` Front/Rear/All gives a differential per driven axle with `differentialRatio`, `limitedSlipRatio` (<= 1 = open) and an even torque split; an anti-roll bar per two-wheel axle; tyres use Jolt's sample model of 10x longitudinal grip, without which the car spins its wheels and the gearbox, which won't shift while they slip over 10%, stays in first), `Motorcycle` (`MotorcycleController`, leaning up to `maxLeanAngle`; the rear wheel driven), `Tracked` (`TrackedVehicleController`: wheels on +X form Jolt's left track, the rearmost wheel of each drives it; steering slows the inner track, and at a standstill turns on the spot with the tracks opposite). Wheel collision: ray, sphere or cylinder cast (rounded for motorcycles), through a `WheelBodyFilter` (`VehicleRecord::wheelFilter`, which outlives the constraint) that skips the vehicle's own body and soft bodies (Jolt's vehicle would push a soft body about as if it were rigid; the chassis still bumps into them). `DriveVehicles` passes the inputs (`throttle` -1..1, `steering`, `brake`, `handBrake`) before each step and wakes the chassis when there are any; `WriteWheels` after the steps puts each wheel entity where Jolt's `GetWheelLocalTransform` has it (suspension, steer, spin; the model axes that map to Jolt's axle and up are the wheel's rest rotation's), in its parent's space. `GetVehicleInfo(entity)`: speed along forward, engine RPM, gear, per wheel contact, suspension (0 out .. 1 up), steer, RPM, slips. Checked on stepped time: the car accelerates to 74 km/h in 5 s shifting into 2nd, turns right with steering +1 (front wheels at +30 deg), stops on the brakes; the motorcycle stays upright at 40 km/h and through a turn; the tank shifts to 4th and turns 81 deg on the spot.

- Joints (`Mariana/Physics/Joint.hpp`, `Joints.cpp`; Jolt's two-body constraints): a `Joint` on an entity holds the body at or above it (the nearest RigidBody on it or an ancestor, else its own static body) to the `connected` entity's (by name, the body at or above it; empty = the world; `toParent` = the body above its own, for nested bodies like chains and ragdolls). While playing the keys drive (`UpdatePlayerControls`, characters relative to the first scene camera's view, else the editor camera's) unless a text field has them or the right mouse button flies the editor camera; `UpdateFollowCameras` runs after the step.
- Player: physics always runs; Player.json spawns can carry a `physics` block or a `ragdoll`, spawn primitives or presets (car, motorcycle, tank, playground, character, course, chain, door, spinner, wrecking ball, pool, ragdoll, flag, drape, jelly, balloon), and `"camera": { "follow": true }` makes the camera chase the driven vehicle or character (characters walk relative to it) (see Layout). The Sandbox's is just `Playground.scene` (the editor's startup scene) with a following camera: hold W and the car sends the dancers flying.
- Physics components are saved with scenes (`physics/source/Serializers.cpp`, registered by `PhysicsWorld::RegisterComponents`; enums by name; driver inputs and broken flags aren't saved). Later, per the plan (ask first): height fields, `KHR_physics_rigid_bodies` import.

### Assets (`Mariana/Assets/`)
- `AssetManager2` is owned by `Application` (`assets` member, declared in the base so it outlives the scene). Per-type `AssetStorage<T>` of `shared_ptr<T>`; `AssetMetadata` per UUID `AssetID` (name, type, `path` = reloadable file, `key` = unique lookup key, `source` = the file its data is in when that isn't `path` (an image, a saved .material; `RegisterAsset(..., source)`, `SetSource`), status, refCount, persistent).
- `AssetHandle<T>` is ref-counted and caches the asset (`Get()` returns `const std::shared_ptr<T>&`, no lookup; `Manager()` is the manager it belongs to); components hold handles (`MeshComponent`, `Animator`, a `MaterialAsset`'s texture slots). Include `Mariana/Assets/AssetManager.hpp` (not just `AssetHandle.hpp`) wherever handles are copied or resolved.
- API: `RegisterLoader<T>(type, exts, fn)`, `Load<T>(path)` (dedupes by key), `LoadAsset<T>(id)`, `RegisterAsset<T>(ptr, type, name, key)` for in-memory/sub-assets, `Find<T>(key)`, `ForEach<T>`, `UnloadUnused()` (cascades until stable), `SetPersistent`.
- Asset types in use: `Texture`, `IMesh`, `Skin`, `Skeleton`, `MaterialAsset`, `AnimationClip`, `AnimationGraph`, `Prefab`.
- `MaterialAsset` (`Mariana/Rendering/MaterialAsset.hpp`) is source-independent (importers, code, the editor make them the same way): `properties` (`PBRMaterialProperties`, mirrors `MaterialProperties` in the shaders; call `MarkDirty()` after changing it), `doubleSided`, `SetAlphaMode(Opaque/Mask/Blend, cutoff)` (writes `alphaCutoff` for Mask and `alphaBlend` for Blend: see-through by alpha, drawn last), `SetTexture(MaterialTexture::BaseColor/Normal/MetallicRoughness/Occlusion/Emissive, handle, SamplerSettings, uvSet)` (keeps `uvSets` in sync, keeps the slot's transform), `SetTextureTransform(slot, TextureTransform{offset, rotation (radians), scale})` (glTF's KHR_texture_transform: scaled, rotated, offset; written into `properties.uvMatrix`/`uvOffset`), `properties.clearcoat`/`clearcoatRoughness` (a varnish layer, 0 = none), `GetTexture(slot)`, `Version()` (bumped by every edit), `Clone()` (same settings and textures, own GPU slot). The renderer owns the GPU side: `material` (the `Material2` bind group, rebuilt while `BindGroupDirty()`) and a slot in the materials storage buffer, uploaded when dirty via `StandardPBRPipeline::UploadDirtyMaterials`.
- `BuiltinAssets`: white sRGB/linear textures, flat normal, default material (no textures) (persistent), primitive meshes (`builtin://...` keys), `WaterNormalTexture` (256² tiling ripples made from integer-frequency sines, mipmapped, `builtin://texture/water_normal`), `Resolve(assets, key)` (the builtin with that key, made if needed; scene files refer to builtins by key), `InstantiatePrimitive` (an entity drawing one with a material of its own).
- Scene files (`Mariana/Importers/SceneFile.hpp`, `SceneFile.cpp`): `.scene` = JSON with `version`, `dependencies` (every file the scene uses, resource paths: models, `.material` files and their images, an animation graph's clip files), `materials` (materials made in memory, e.g. primitives' own and "Make unique" copies, in the `.material` format with textures by `asset` reference; `MaterialJson` (private `Importers/MaterialJson.hpp`) is that format's writer and reader, shared with `MaterialFile`) and `entities` (parents first: `id`, `name`, `parent`, `components` by ECS name, `tags`). `Save(scene, assets, file, error)`, `Load(scene, assets, file, error, warnings*)` (adds to the scene; Clear it first), `Dependencies(file)`. Components are described once for both directions by a visitor: `SceneFile::RegisterComponent<T>(name, [](SceneArchive& a, T& c) { a.Field("mass", c.mass); ... })` / `RegisterTag<T>(name)`; `SceneArchive` has `Field` for numbers, bools, strings, vectors, quaternions ([x, y, z, w]), float arrays and lists, enums (as numbers, or by name with a names list), `Asset`/`Assets` (references: `/Models/X.gltf#mesh/3` for what a file holds (loading the file), `/Materials/A.material` for a whole file, `/Textures/x.png#srgb`, `builtin://...`, `#material/N` for the file's own) and `List` of objects; a missing field keeps the component's value. The engine registers LocalTRS, MeshComponent, ShadowCasterTag, CameraComponent, AnimationTargetEntity, SkinComponent and Animator (skeleton, named clips, graph, speed, playing, the clip playing with its loop and time); derived transforms aren't saved, other components are left out with a warning. Asset keys are lower case on Windows, so references take the file's real spelling (`canonical`) and `FileSystem::ToResourcePath`. A save, load and save round trip gives the same file (checked on the 366-entity playground).
- `Submesh::materialIndex` = index into `MeshComponent::materials` (the glTF primitive index; a `MeshSection`'s `materialIndex`).

### Shaders (`engine/resources/Shaders/`)
`test.wgsl` = live PBR shader (forward pass) (GGX, shadow PCF; group 0 = UBO/camera/DrawInfo/ModelData/Material/Bones/shadow maps 0-3 (bindings 6-9) + comparison sampler (10) + sky cubemap (11) + its sampler (12), group 1 = albedo 0, normal 1, metallicRoughness 2, occlusion 3, emissive 4, then one sampler per texture at 5-9 (`albedoSampler` ... `emissiveSampler`), matching the names `SceneRenderer::BuildMaterialBindGroups` binds). Each texture reads `uv` or `uv1` by bit in `MaterialProperties.uvSets`, moved by its texture transform (`textureUV`: `uvMatrix[i]` rows and `uvOffset[i]`; the prepass and shadow alpha tests transform the base color UV the same way); COLOR_0 multiplies base color and alpha; light is gathered as diffuse (sun + sky) and specular (sun + sky reflections + clearcoat), summed for opaque surfaces and, for blended ones (`alphaBlend`), output premultiplied: diffuse times alpha plus specular, alpha = alpha (glass and water keep their highlights), and they skip the screen-space AO; clearcoat (`Material.clearcoat` > 0) adds a GGX lobe and a sky reflection at `clearcoatRoughness` along the geometric normal (normal maps bend only the base), F0 0.04, dimming the layer below by its Fresnel; the vertex shader passes `mirror` (-1 for a negative determinant), which flips the face side and the bitangent; fragments with no normal (points/lines without NORMAL) are drawn unlit. Lighting = sun (`UBO.sunColor`, full-strength shadows) + sky: diffuse from `skyIrradiance(N)` (the SH) and reflections from `skyReflection()` (cubemap mip picked from roughness, fading to the SH when very rough) weighted by `envBRDFApprox` (Karis' analytic split-sum fit), both times AO. Normals: the interpolated tangent frame is re-orthonormalized per pixel and bent by the normal map (xy scaled by `normalMapStrength`); back faces (double-sided only) flip the whole frame via `front_facing`; the shadow lookup offset uses the geometric normal. Both the PBR and shadow shaders read their per-instance data from `DrawInfo[instance_index]` (`transformIndex`, `materialIndex`, `boneOffset`) and skin vertices with `skinMatrix()` (blend of up to 4 `Bones[boneOffset + joint]` matrices, identity when `boneOffset == NO_SKIN`). `skybox.wgsl` live (samples mip 0 only, turned by `skyParams.z`; writes the cubemap pre-inverted through ACES and `camInfo.exposure`, so it reaches the screen as authored, and alpha 0 so it never blooms). `prepass.wgsl` (depth/normals/pick). Effect shaders live in `Shaders/Effects/` (gtao, gtao_blur, bloom_down/up/apply, tonemap, present). In test.wgsl, alpha-tested materials output coverage (alpha sharpened around the cutoff) for alpha to coverage, and the `AmbientOcclusion` graph texture (binding 13, `textureLoad` at the pixel, clamped so the 1x1 fallback works) is combined with the material AO by `min` and applied to sky light only, with `multiBounceAO` and `specularOcclusion`. `outline.wgsl`, `test_old.wgsl` are legacy. WGSL struct layouts must match the C++ structs in `StandardPBR.hpp` / `ICamera.hpp` / `MaterialAsset.hpp`.
- Color: the scene renders linear HDR; only the final effect (tonemap.wgsl, or present.wgsl) tonemaps and encodes with `linearToSrgb`, because the swapchain is deliberately UNORM (`Window::GetSurface`). Color textures are sRGB formats (decoded on sample). `CameraInfo.exposure` is the camera's exposure (`ICamera::SetExposure`; set by the pipeline, 1.5 in Default.pipeline). Emissive can exceed 1 (glTF `KHR_materials_emissive_strength`, or the HDR Emissive control per material in the Mesh inspector). ImGui textures (asset thumbnails) are UNORM.

## Known quirks
- Resting bodies sink up to the penetration slop (5 mm) into what they land on (a dropped 1 m ball rests at y 0.495).
- `FileReader::LoadRawString` logs and throws `std::runtime_error` on a missing file.
- File's Preferences and Exit, the Help menu and Edit's Cut/Copy/Paste are TODO placeholders; `Application::Quit()` is declared but not defined.
- Scene files don't keep the editor camera, the selection or an Animator's graph parameters; recent scenes last only for the session.
- `WorldXform.id` slots are never reused, and `Buffer::Write` throws past 131072 transforms.
- `editor/imgui.ini` is tracked in git and changes whenever the layout does. The web build has no ini (it isn't packaged), so its windows start at ImGui's defaults.
- `projects/Sandbox/Models/Sponza/` (Khronos glTF-Sample-Assets Sponza, 51 MB, `.gltf` + external textures) is committed; the editor's web build preloads the whole project, so it makes `index.data` ~110 MB with CarConcept (Khronos glTF-Sample-Assets, glTF-JPG, ~10 MB; the player's ~13 MB). CarConcept's iridescence, material variants and clearcoat textures aren't rendered and its glass blends rather than refracts.
- Blended surfaces aren't in the prepass, so a click on them doesn't pick them (select them in the Hierarchy) and they don't take part in GTAO; they cast no shadow and are sorted per draw (by their bounds' center), not per triangle. It has 3 alpha-masked, double-sided materials (ivy, flowers, chains), handy for testing those paths; the arcades get only sky light, so they stay darker than the courtyard.
